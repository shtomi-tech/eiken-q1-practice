# 問題セットの形式・構造監査

対象リポジトリは `C:\Users\shtom\dev\eiken-q1-practice` のみ。以下のパスはリポジトリ直下からの相対パス。
Python 3（`py -3`）を使用する。監査は読み取り専用で、データを書き換えない。

**基準は実行時点の manifest に登録された `eiken1-*`。** セット数や形の標準値を文書へ固定せず、
`--baseline` で実データから算出する。1級セットの追加・変更があれば基準も追随する。

**この監査は形と構造だけを見る。** 語義の正しさ、和訳の自然さ、難易度、正答の一意性、出典の妥当性は
対象外（それらは `add-question-set` の 6節「正答一意性の独立レビュー」の担当）。

## 0. 監査の範囲を決める

1. 対象を確定する。新規セット1件か、級まるごとか、manifest 登録済みの全セットか。
2. **既定は読み取り専用。** 修正依頼が明示されていなければ、報告までで止める。
3. 修正するときは **`data/*.json` を直接編集しない。** JSONは生成物で、
   正本は `scripts/build_q1_*_data.py`。ビルドスクリプトを直して再生成する
   （手順は `.claude/skills/add-question-set/SKILL.md` の4節）。

## 1. 機械監査を回す

```powershell
py -3 scripts/audit_question_set.py --baseline          # 基準値を確認
py -3 scripts/audit_question_set.py eiken1-mock-9       # セット指定
py -3 scripts/audit_question_set.py --grade eikenp2     # 級指定
py -3 scripts/audit_question_set.py                     # 全セット
py -3 scripts/audit_question_set.py --severity error    # ERRORだけ
py -3 scripts/audit_question_set.py --json              # 機械可読出力
```

ERROR が1件でもあれば終了コード1（`--no-fail` で常に0）。
出力は `[深刻度] 検査ID 位置: 内容` の形。位置は `set` か `Q12` か `Q12/語句`。

先に `py -3 scripts/check_q1_data.py` と `npm test` を通しておく。あちらが見る契約
（manifest 整合・語彙重複・原形辞書・coreImage の全級整合）は監査の前提で、この監査は重複して見ない。

## 2. 検査IDの読み方と直し方

深刻度は **ERROR = 基準セットが必ず満たす条件の違反**、**WARN = 基準からの逸脱（判断が要る）**。

| ID | 内容 | 直し方 |
| --- | --- | --- |
| S01 | 設問番号が1からの連番でない | `QUESTIONS` の並びと `q` を直す |
| S02 / S03 | 設問あたりの語彙が4件でない／設問のない語彙番号 | `DETAILS` の `q` を直す |
| S04 | 設問数・熟語設問数が同種セット（級×模試/過去問）の標準と違う | 意図的なら報告して残す。取り違えなら語句を増減 |
| S05 | 熟語設問が末尾に連続していない | 熟語設問を末尾へ寄せる |
| S06 | 空所表記がセット内で混在 | `(   )` に統一（AUTHORING.md の規則） |
| S07 | 空所表記が同種セットの標準と違う | 表示は同じなので優先度は低い。§4の既知の逸脱を参照 |
| S08 / S09 / S10 | meta の不足／questions と vocab の meta 不一致／counts が実データと不一致 | ビルドスクリプトの `META` を直して再生成 |
| S11 | manifest の総数が実データと不一致 | `py -3 scripts/check_q1_data.py --update-manifest` |
| Q01 / Q02 | 選択肢が4件でない・重複・answerIndex 範囲外 | `QUESTIONS` を直す |
| Q03 | 空所が1か所でない | 設問文を書き直す |
| Q04 | 設問文の語数が基準レンジ外 | 級が下なら想定内（§4）。1級セットなら書き直す |
| Q05 | 正答語・誤答語が設問文に出ている | **ダミー側を差し替える。**設問文の語を消すと正答を一意にしている文脈が壊れる |
| Q06 / Q07 | 和訳がない／和訳に空所記号が残る | `translation` を直す |
| Q08 / Q09 / Q10 | 選択肢と語彙項目の対応、`is_answer` と `answerIndex` の食い違い | `DETAILS` の `is_answer` と `QUESTIONS` の `answerIndex` を突き合わせる |
| Q11 | 同一設問で `meaning` が重複 | 誤答の語義を書き分けるか語句を差し替える |
| Q12 | 同一設問に単語と熟語が混在 | 設問単位で単語／熟語をそろえる |
| Q13 | 選択肢の品詞が3種類以上 | 品詞が割れると意味を読まずに消去できる。誤答をそろえる |
| Q14 | 正答位置の偏り（1割未満または4割超） | `choices` の並びと `answerIndex` を**同時に**直す。語彙JSONは追随する |
| V01 | 語彙フィールドの不足 | `ipa` だけならWARN。通常の単語は `enrich_flashcard_fields.py` を使う。multi-word modal などを意図的にword扱いする場合は、IPAを任意とする契約または許容WARNを監査記録へ明記し、警告だけを黙って抑止しない |
| V02 | `collocation` / `etymology` が付いている | アプリが参照しない。新規セットでは付けない |
| V03 | 熟語に `ipa` が付いている | 基準セットの熟語は `ipa` を持たない |
| V04 | `meaning` / `example` / `exampleTranslation` / `pos` が空 | ビルドスクリプトを直す |
| V05 | 例文の見出し語句が1回でない | 語境界つきで数える。0回なら語形違い、2回以上なら例文を書き直す |
| V06 | 例文が8語未満 | 書き直す |
| V07 | 例文が句読点で終わっていない | 末尾を直す |
| V08 / V09 | `coreImage.chain` が3段未満／gloss が空 | `docs/CORE_IMAGE_AUTHORING.md` が正本 |
| V10 | 句動詞（`coreImage.particle` 付き）が0件（ERROR）／25%未満（WARN） | 前置詞句だけだと暗記カードの不変化詞パネルと仲間例が働かない。熟語を入れ替える |
| X01 / X02 / X03 | 設問文・例文・例文訳の骨格が重複（同一セット内はERROR、セット間はWARN） | 別セットからの使い回し。設問文・例文を書き直す |

## 3. 機械監査で見えない形式（目視で確認する）

script は語の並びしか見ない。以下は出力を見ながら人が判断する。

- **誤答が文脈上明確に成立しないか。** 「文法的には入るが意味が弱い」は不可。
- **選択肢の統語クラス**（前置詞句／副詞句／接続詞句）がそろっているか。`pos` が同じでも割れることがある。
- **場面の散らばり。** 同一場面（学校・仕事・環境など）が連続していないか。
- **会話文 `A: … B: …` の比率**が同級の既存セットと同水準か。
- **語彙レベルが級相当か。** 1級なら他級から流用した平易語が混じっていないか。
- **米語基調でそろっているか**（`noticeboard` などの英用法は既存データと食い違う）。

## 4. 既知の逸脱（基準セット側の状態。2026-09-08 時点）

これらは監査の誤検知ではなく、基準セット自身に残っている逸脱。新規セットの判断材料にする。

- `eiken1-mock-8`: 句動詞0件（V10 ERROR）。他の1級セットは16件中13〜16件が句動詞。
- `eiken1-mock-6/7/8/9`: 空所が `(   )`、それ以外の1級セットは `( )`（S07）。
  HTMLでは同じ見た目になるので実害はないが、AUTHORING.md の規則は `(   )`。
- `eiken1-mock-9`: 25問中10問の設問文が `eiken1-mock-8` と同一（X01）。選択肢だけ差し替えたもの。
- 5級・iuhw は設問文が基準レンジ（13〜45語）より短く、Q04 が多く出る。級相応なら想定内として報告する。
- `iuhw-set-1` / `iuhw-set-2`: 句動詞0件（V10 ERROR）。IUHW は particle 機構を使わず、
  熟語は term ステップ2件＋導出1件の3段チェーンで統一する設計。
  正本は `docs/IUHW_ALIGNMENT.md` / `docs/IUHW_BASIC_EXAM_SET_2_REVIEW.md`。
- `iuhw-set-2`: 熟語設問数3（S04、標準1）。ユーザー依頼で熟語を2→12件へ増やし Q13〜15 を熟語問題化した。
  正本は `docs/IUHW_BASIC_EXAM_SET_2_REVIEW.md`。

## 5. 報告

- 結論を先に。**ERROR件数 / WARN件数 / 対象セット数**、次に修正が要るものだけを列挙する。
- 各指摘は `検査ID 位置: 内容` と、直す対象ファイル（ビルドスクリプト名）を `path:line` で示す。
- セット単位の監査記録は `docs/<SET>_REVIEW.md` に残す（既存の `MOCK_9_REVIEW.md` 等が型）。
- 修正した場合は、**再生成 → `py -3 scripts/audit_question_set.py <id>` → `npm test`** の順で再検証し、
  実行結果を報告する。監査だけの依頼なら修正しない。

## 6. 監査後に修正へ進む場合

監査の完了は修正の承認でも、教材内容の合格でもない。修正依頼が明示された場合だけ、次の境界を
実装計画へ引き渡す。

1. **内容を先に確定する。** 選択肢・設問文・正答位置・語句を変える前に、
   `.claude/skills/add-question-set/SKILL.md` の正答一意性レビューで、文法・意味・コロケーション・
   級相当性を確認する。構造検査の通過だけで内容品質を合格扱いしない。
2. **語句種別を空白で推定しない。** multi-word modal や時制表現も空白を含む。
   builder は設問番号集合またはauthoring正本の明示メタデータを使い、設問内4択を同じ種別へ揃える。
3. **問題の同一性を保護する。** 設問順を変える前に、`datasetId` と `q` に紐づく既存進捗への影響を
   確認する。並べ替えが不可避なら、互換方針・移行・リセット範囲を計画へ明記し、判断なしに進めない。
4. **正本と生成物を一体で扱う。** builder、専用checker、questions JSON、vocab JSONを1セットの
   write set とし、別セットや共通manifestの既存差分と混ぜない。
5. **検証を閉じる。** builder再生成 → 専用checker → `check_q1_data.py` → 対象監査でERROR 0 →
   `npm test` の順に確認する。公開依頼がある場合は対象ファイルだけをstageし、CI完了後に公開JSONも確認する。

## 7. 基準を更新するとき

- 閾値は `scripts/audit_question_set.py` 冒頭の定数（`STEM_WORDS_MIN` 等）。
  変更したら `--baseline` と `--grade eiken1` を回し、**基準セットが ERROR 0 のままか**を必ず確認する。
- 基準セットを1級以外へ移すときは `BASELINE_PREFIX` を変える。
- 検査を足したら、この SKILL.md の §2 の表にも同じIDで追記する。
