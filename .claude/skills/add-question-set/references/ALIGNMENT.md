# 模試第6回を基準にした整合

`SKILL.md` から、**「模試第6回を正として既存セットをそろえる」依頼のときだけ**読む。新規セットの追加だけなら読まない。

## 基準セット: 1級模試第6回

`eiken1-mock-6` を1級模試の基準セット（参照実装）として扱う。第6回の語句・正答・出典を他セットへコピーするのではなく、構造、作問・語彙項目の完成条件、語源・核心イメージ、暗記カード・音声、検証・公開の品質基準を合わせる。

### 参照する正本

- `scripts/build_q1_mock_6_data.py`: 第6回の問題・語彙JSONを生成する正本。
- `data/questions_1_mock-6.json` / `data/vocab_1_mock-6.json`: 生成結果と比較用の基準スナップショット。直接編集しない。
- `scripts/check_mock_6_data.py`: 25問 / 100語句（84語 / 16熟語）、4択、例文、重複、核心イメージ等の第6回専用検査。
- `docs/MOCK_6_REVIEW.md`: 出典、置換した選択肢、独立レビュー、C型熟語の判断記録。
- `data/word_origins.json`、`data/lemmas.json`、`assets/audio/vocab/1/mock-6/`、`assets/audio/lemma/`: 語源、原形表示、出題形音声、原形音声の完成状態を確認する参照先。

### 第6回に合わせる項目

- 同型の1級模試は25問 / 100語句を基本とし、84語 / 16熟語の構成、設問と語彙項目の対応、4択1正答をそろえる。
- 全語句に意味・品詞・例文・例文訳・語源をそろえ、単語のIPAは `enrich_flashcard_fields.py` で補完する。1級模試の語源チェーンと、熟語の核心イメージは第6回と同じ完成度を目指す。
- 合わせるのはフィールドの揃い方、例文の独立性、語源・核心イメージの説明密度、品詞・意味の明確さ、出題形・原形音声の扱いである。
- 熟語の核心イメージは語の意味から個別に判断する。第6回の14件 + C型2件（`come clean` / `rooted for`）は判断例であり、別セットへ phrase・chain・C型判定をコピーしない。
- 出題形音声を全語句に用意し、暗記カードで原形表示する語は原形MP3も用意する。Azureキーは環境変数だけで扱う。
- 正答一意性、本文への選択肢露出、例文の骨格重複、重複語句、公開成果物まで機械検査と独立レビューで確認する。

### 第6回からコピーしない項目

- 原本固有の設問文、語句、正答、選択肢、出典、置換理由は各セットのものを保持する。第6回は作法の基準であって、問題内容の共通原本ではない。
- 既存セットの `datasetId`、設問番号、進捗キー、公開URLは、ユーザーが明示しない限り変更しない。
- 25問 / 100語句や84語 / 16熟語を、公式過去問・別級・iuhwへ機械的に適用しない。各セットの形式・出典・IDを優先する。
- 対象セットのビルドスクリプトやJSONを第6回のファイルで丸ごと置き換えない。対象セット自身のビルドスクリプトを正本として、差分だけを整える。第6回のスクリプトは構造・検査・作法の参照だけに使う。
- 第6回の語句を別セットへ移す場合も、`SKILL.md` 3節の重複制約をそのまま適用する。基準セットは語彙移植用の除外リストではない。

## 手順

1. `data/manifest.json` から対象IDを確定し、同型の1級模試と公式過去問・別級を分ける。
2. 変更前に、基準との差分を下の監査軸で読み取り専用で監査する。複数セットなら `docs/<SET>_ALIGNMENT.md` に残す。
3. 差分を「合わせる」「内容判断が必要」「保持」に分類する。正答や出典を変える差分は、ユーザーの明示なしに修正しない。
4. 一度に1セットだけ、対象のビルドスクリプト・補助データ・音声を更新し、生成、機械チェック、独立レビュー、ブラウザ確認まで完了させる。
5. 監査・整合計画だけの依頼では、コード・データ・音声・manifestを変更しない。実装依頼へ進んだ後も、各セットを個別コミット・個別検証する。

## 監査軸

| 監査軸 | 模試第6回の基準 | 判定・扱い |
| --- | --- | --- |
| 構造・件数 | 25問 / 100語句、84語 / 16熟語、設問と4択・語彙の対応 | 同型なら合わせる。別形式には強制しない |
| 内容品質 | 全語句の意味・品詞・例文・例文訳・語源、4択1正答 | 欠落を補う。正答や原本固有の内容は保持する |
| 語源・核心イメージ | 84語の語源チェーン、熟語は意味に基づく個別判断 | 説明の完成度を合わせる。chainをコピーしない |
| 原形・音声 | 出題形音声、必要な動詞の原形表示・原形MP3 | `flashcardLemmas` とMP3を照合する。出題形を上書きしない |
| 出典・ID・進捗 | 第6回固有の出典記録と `eiken1-mock-6` | 対象セット固有の出典・ID・進捗キーは保持する |

差分は `docs/<SET>_ALIGNMENT.md` に、次の分類で残す。

```text
| 監査軸 | 基準 | 対象セットの現状 | 判定（合わせる / 内容判断 / 保持） | 根拠・変更元 |
```

## 検査

整備前は `--audit` で不足項目を列挙し、整備後は通常モードで0件になることを確認する。

```bash
py -3 scripts/check_eiken1_alignment.py --dataset-id eiken1-mock-1 --audit
py -3 scripts/check_eiken1_alignment.py --dataset-id eiken1-mock-1
py -3 scripts/check_mock_6_data.py
py -3 scripts/check_<set>_data.py
npm test
```

`check_eiken1_alignment.py` は公式過去問の22問/88語句と模試の25問/100語句を区別し、既存の設問内容・ID・進捗キーを変更しない。`check_mock_6_data.py` は第6回の固定基準を検査する専用スクリプトで、他セットの定数を書き換えて流用しない。整合対象には対象セット専用の検査を用意する。

差分表の各行について、対象セットの生成元・検査結果・保持判断を確認してから次のセットへ進む。件数だけを合わせて完了扱いにしない。

## 組み込み・公開

整合では、通常はmanifestのID集合、`EXPECTED_IDS`、公開URL、進捗キーを変更しない。件数や表示を変える場合だけ、ユーザーの依頼範囲に含めて更新する。公開確認の手順は [CHECKS.md](CHECKS.md) の「Pages公開確認」を使う。
