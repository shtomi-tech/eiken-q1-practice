# 英検1級 日次・週次学習目標と語彙到達予測の実装計画

> 対象: `static/mode-q1.js` / `static/styles.css` / `DESIGN.md` / `README.md` / 新規テスト
> 状態: 計画（未着手）
> 作成日: 2026-08-25

## 0. 目的

英検1級の通常問題について、利用者が総問題数と1日あたりの目標を設定し、次をホームで確認できるようにする。

- 総目標まで、あと何問を新規に解く必要があるか
- 今日と今週の新規回答数、および各目標までの残数
- 学習できない日があっても、週内の残り日数へ必要量を再配分した目安
- 現在のペースで1週間後、1か月後、3か月後、半年後、1年後に学べる語句数
- 準1級までの9,000語を起点として、英検1級の目標14,000語へ到達する予想日

この計画は実装範囲を定めるものであり、現時点ではコード・保存形式・UIを変更しない。

## 1. 確定した仕様

### 1.1 対象範囲と「1問」の定義

- 対象は `gradeOf(datasetId) === "eiken1"` の通常問題すべてとする。
- `eikentopic-*` のテーマ別問題は含めない。
- 問題は `(datasetId, q)` の組で一意に識別する。回をまたいで同じ設問番号があっても別問題として扱う。
- 本番形式4択へ初めて回答した時点で「新規に1問解いた」と数える。正誤は問わない。
- 同じ問題の解き直し、意味チェック、間隔復習は日次・週次・総問題数へ重複加算しない。
- 現在の収録範囲は191問・764語句。件数はUIへ固定値で埋め込まず、manifest配下の1級通常データから算出する。

### 1.2 設定値

| 設定 | 初期値 | 制約・意味 |
| --- | ---: | --- |
| 総問題目標 | 191問 | 1以上、現在収録されている1級通常問題数以下 |
| 日別問題目標 | 8問 | 1以上の整数。実用上の上限は収録問題数 |
| 週の開始曜日 | 月曜 | 日曜〜土曜から選択可能 |

- 週間目標は常に `日別問題目標 × 7` とし、独立した入力値は持たない。
- 日別目標を変更したら、週間目標・語句予測・14,000語到達予想を同時に再計算する。
- 週の未達分は翌週の週間目標へ上乗せしない。総問題目標の残数にはそのまま残る。
- 総問題目標を既回答数より小さく変更した場合は、残数0問・達成済みとして表示する。
- 将来問題が追加されても、既存利用者の保存済み総問題目標を無断で増やさない。未設定の新規利用者だけ、その時点の収録問題数を初期値にする。

### 1.3 語句数と期間の定義

- 1問につき4つの新しい語句を学ぶ計画値として、`1日の新規語句数 = 日別問題目標 × 4` とする。
- 期間予測は次の固定日数を使用する。カレンダー月の日数差では計算しない。

| 表示 | 日数 | 日別8問の初期値 |
| --- | ---: | ---: |
| 1週間後 | 7日 | 224語句 |
| 1か月後 | 30日 | 960語句 |
| 3か月後 | 90日 | 2,880語句 |
| 半年後 | 180日 | 5,760語句 |
| 1年後 | 365日 | 11,680語句 |

- 上記は教材収録数で打ち止めにしない「理論上の学習量」とする。
- 同じカード内に「現在、このアプリの英検1級通常問題には764語句を収録」と注記し、このアプリだけで長期予測分をすべて学べるという誤読を防ぐ。
- 収録語句数も固定値ではなく、1級通常データの `(datasetId, itemKey)` を使って算出する。

### 1.4 14,000語への到達予想

- 既存の `VOCAB_GOALS.eiken1` と同じく、準1級までの9,000語を習得済みの起点とする。
- 現在語彙数は `9,000 + このアプリで学習済みの1級通常語句数` とする。
- 学習済み語句数は、初回答済み問題に属する語句を `(datasetId, itemKey)` で重複排除して数える。
- 現在語彙数は14,000でクランプする。
- 残り語数と到達日を次で計算する。

```text
dailyVocabulary = dailyQuestionGoal * 4
remainingVocabulary = max(0, 14000 - currentVocabulary)
daysToGoal = ceil(remainingVocabulary / dailyVocabulary)
estimatedDate = 今日（利用者のローカル日付） + daysToGoal
```

- 初期状態では残り5,000語、32語句/日なので157日が目安になる。
- 到達日は「設定した目標ペースを今日以降も続けた場合」の予想として表示し、実績に応じて毎日更新する。
- 14,000語と前級9,000語は公式公表値ではないため、既存カードの「目安です」「前級までは習得済みとして計算」の注記を維持する。

## 2. 現行実装と変更の継ぎ目

### 2.1 進捗

- 設問進捗は `progress.units[q]` に保存され、`onPracticeAnswer()` で `learned`、`attempts`、`lastAnsweredAt`、正誤状態を更新している。
- `lastAnsweredAt` は解き直しのたびに更新されるため、初回答日の集計には利用できない。
- `progress.history` には `{ at, kind: "question", q, result }` が最大500件保存される。
- 非アクティブ回は `progressFor(datasetId)` で読み、級横断の描画中は `withProgressReadCache()` を使える。

### 2.2 級横断データ

- `ALL_DATASETS` はmanifest全件、`DATASETS` は利用者の級に絞られた一覧である。
- 1級通常セットの列挙は、テーマ別を混ぜないため `Object.keys(ALL_DATASETS).filter(id => gradeOf(id) === "eiken1")` を正本とする。
- `loadPooledItems("eiken1")` は各語句へ `_datasetId` を付けて読み込む既存経路なので、語句数と学習済み語句数の集計に再利用する。

### 2.3 ホーム

- `renderHomeContent()` は「今日の学習」カードを先に描画し、その直後に `vocabGoalCard()` を置いている。
- 日次・週次・総問題目標は、主CTAを増やさず「今日の学習」カード内の進捗領域として追加する。
- 長期語彙予測と14,000語到達日は、既存の `vocabGoalCard()` 内へ追加する。問題計画と語彙計画を別カードへ分裂させない。

### 2.4 クラウド

- 生徒別進捗は `app="eiken2-q1"` の1行に `{ datasetId: progress, _meta: {...} }` として保存される。
- `app_save_progress_dataset` は既存 `_meta` と新しい `p_meta` をJSONマージするため、`_meta.studyPlanV1` を追加しても他のメタデータを失わない。
- 匿名利用は `scopedStorageKey()` のない通常localStorage、生徒別利用は同関数による生徒別キーを使う。

## 3. 保存形式

### 3.1 初回答時刻

各セットの `progress.units[q]` に、初回答時だけ不変の時刻を追加する。

```js
{
  learned: true,
  attempts: 1,
  firstAnsweredAt: "2026-08-25T10:30:00.000Z",
  lastAnsweredAt: "2026-08-25T10:30:00.000Z"
}
```

- `onPracticeAnswer()` で、既存値が有効なISO日時でない場合だけ `firstAnsweredAt` を設定する。
- `lastAnsweredAt` は従来どおり毎回答時に更新する。
- 日付境界の判定では、ISO文字列をUTC日付のまま切り出さず、`Date` に戻して利用者のローカル時刻で比較する。

### 3.2 学習計画設定

新規キー `STUDY_PLAN_KEY = "eiken_q1_study_plan_v1"` を追加し、次を保存する。

```js
{
  version: 1,
  questionGoal: 191,
  dailyQuestionGoal: 8,
  weekStartsOn: 1
}
```

- `weekStartsOn` はJavaScriptの `Date#getDay()` と合わせ、`0=日曜 ... 6=土曜` とする。
- 読み込み時はオブジェクト形状・整数・範囲を検証し、項目単位で既定値へフォールバックする。
- 未知の項目は削除せず、保存時も可能な範囲で保持する。将来拡張時の巻き戻し余地を残す。
- ローカル保存は `localStorage.setItem(scopedStorageKey(STUDY_PLAN_KEY), ...)` を使う。
- クラウドでは同じ値を `_meta.studyPlanV1` に保存する。
- 起動時の優先順位は、認証済み共有URLではクラウド値、クラウドに値がなければ生徒別ローカル値、匿名利用ではローカル値、最後に既定値とする。

### 3.3 クラウドパッチ

メタデータ生成を1か所へまとめる。

```js
function cloudMeta() {
  return {
    lastDatasetId: state.datasetId,
    studyPlanV1: studyPlan,
  };
}
```

- `getPatch()` と `saveProgressFor()` の `meta` は `cloudMeta()` を使い、通常の問題回答でも設定値が保持されるようにする。
- `collectAllProgress()` も `_meta: cloudMeta()` を含め、将来フル保存経路へ戻っても設定を失わないようにする。
- 設定変更時はローカルへ即時保存した後、現在セットの進捗と `cloudMeta()` を `cloud.queueSave()` へ渡す。
- `applyCloudProgress()` はセット進捗の適用に加え、検証済みの `_meta.studyPlanV1` を生徒別ローカルキーへ反映する。
- `APP_ID`、既存セットID、進捗キー、旧 `eiken-q1-practice` 行は変更・削除しない。

## 4. 既存進捗の移行

初回答時刻を持たない既存データを、今日の実績へ一括計上してはいけない。

1. 各1級通常セットについて、`progress.history` の `kind === "question"` を設問番号ごとにまとめる。
2. `units[q].firstAnsweredAt` がなく、履歴に有効な日時があれば、最古の `at` を初回答時刻として補完する。
3. `learned === true` または `attempts > 0` だが履歴にも日時がない場合は、総問題目標の回答済み数には含める一方、日次・週次実績からは除外する。推測した日時は作らない。
4. 移行は冪等にし、既存の `firstAnsweredAt`、履歴、正誤、復習状態を上書きしない。
5. 補完が発生したセットだけローカル保存し、共有モードでは既存のセット単位パッチでクラウドへ同期する。
6. 移行済みマーカーを進捗内に持たせ、ホーム描画のたびに再保存しない。

総回答済み判定は互換性のため、次のいずれかを満たす設問とする。

```text
valid(firstAnsweredAt) OR attempts > 0 OR learned === true
```

新規コードでは `firstAnsweredAt` が必ず残るため、日付別集計はこの値だけを使える。

## 5. 集計ロジック

副作用のない関数として分離し、UIを生成せずにテストできるようにする。

### 5.1 必要な関数

- `gradeQuestionEntries("eiken1")`: `{ datasetId, q, unit }` の配列を返す。
- `answeredQuestionEntries(...)`: 初回答済みだけに絞る。
- `startOfLocalDay(date)`: ローカル時刻の当日0時。
- `startOfWeek(date, weekStartsOn)`: 選択曜日から始まる週のローカル0時。
- `nextWeekStart(...)`: 現在週の排他的終了境界。
- `studyPlanSummary(now, plan, entries)`: 日次・週次・総目標の表示値を返す。
- `vocabularyForecast(plan)`: 7/30/90/180/365日の理論値を返す。
- `vocabularyGoalForecast(now, plan, learnedVocabulary)`: 14,000語までの残数・日数・日付を返す。

### 5.2 日次・週次

```text
answeredToday = firstAnsweredAt が [今日0時, 明日0時) にあるユニーク問題数
answeredThisWeek = firstAnsweredAt が [週開始0時, 次週開始0時) にあるユニーク問題数
dailyRemaining = max(0, dailyGoal - answeredToday)
weeklyGoal = dailyGoal * 7
weeklyRemaining = max(0, weeklyGoal - answeredThisWeek)
daysRemainingIncludingToday = 次週開始までに含まれるローカル暦日数
adjustedDailyTarget = ceil(weeklyRemaining / daysRemainingIncludingToday)
overallRemaining = max(0, questionGoal - answeredOverall)
```

- `daysRemainingIncludingToday` は週最終日でも1とし、0除算させない。
- 日別目標を超えた分は週間実績へそのまま入り、調整値を下げる。
- 週を越えた実績は現在週の分子へ入れない。
- DSTがあるタイムゾーンでも1日を固定24時間として加算せず、`setDate()` とローカル0時を使う。日本では出番が少ないが、日付は油断すると急に国際派になる。

## 8. テスト計画

### 8.1 ロジック契約

`scripts/check-study-plan.cjs` で時刻を固定し、少なくとも次を検証する。

- 同じ `(datasetId, q)` の解き直しは1問のまま
- 別セットの同じ `q` は別問題
- 正解・誤答とも初回答へ加算
- 意味練習履歴は除外
- 週開始曜日が月曜・日曜・任意曜日で正しく切り替わる
- 週開始日当日、週最終日、月またぎ、年またぎ
- ローカル23時台とUTC日付の差で翌日扱いにならない
- 週間56問、残り38問・4日なら調整値10問
- 日・週・総目標を超えても残数は0未満にならない
- 7/30/90/180/365日の予測値
- 9,000語起点、32語句/日、残り5,000語なら157日
- 日別目標変更で週間目標と全予測が連動
- 無効な保存値が安全な既定値へ戻る

### 8.2 移行・保存契約

- 履歴の最古の設問回答だけを `firstAnsweredAt` に補完する
- 日時不明の旧回答は総数へ入るが、今日・今週には入らない
- 既存 `firstAnsweredAt` を上書きしない
- 移行を2回実行してもデータが変わらない
- 生徒A/Bと匿名利用で設定キーが分離される
- クラウド `_meta.lastDatasetId` を保持したまま `studyPlanV1` をマージする
- 旧 `APP_ID` へ書かない
- トークンや進捗JSON全体をテストログへ出さない

### 8.3 ブラウザ確認

ローカルサーバーで、匿名利用と生徒別URLの両方を確認する。

1. 英検1級ホームで総目標・今日・今週・語彙予測が表示される
2. 新規問題へ初回答すると、総数・今日・今週が各1増える
3. 同じ問題を再回答しても増えない
4. 日別目標と週開始曜日を変更すると全表示が即時再計算される
5. リロード後も設定と初回答時刻が残る
6. 共有モードでは別端末相当の再読込で同じ設定が復元される
7. 2級・準1級などでは英検1級専用計画UIを表示しない
8. 320 / 375 / 720 / 1280pxで横スクロール、切れ、重なりがない
9. キーボードだけで開閉・入力・保存・キャンセルできる
10. コンソールエラーと失敗リクエストがない（ローカルの `static/config.json` 404は既存仕様として切り分ける）
