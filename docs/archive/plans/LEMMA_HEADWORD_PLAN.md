# 暗記カード・意味4択を原形基準へ統一する実装計画

更新日: 2026-08-26
状態: 公開済み（2026-08-26）

## 1. 目的

暗記カードと意味4択では、問題文に合わせて変化した語形ではなく、辞書で引く形を学習対象にする。

- 英語見出しを原形・単数形へ統一する。
- 日本語訳を辞書形へ統一する。
- IPAと音声も原形へ統一する。
- 同じ原形に複数の既存語義がある場合は、収録済みの語義を失わないよう一つの辞書エントリへ統合する。
- 問題スロット、既存進捗、本番形式の出題形は維持する。

## 2. 確定仕様

### 2-1. 対象

- `data/lemmas.json` の原形マップ対象すべて。
- 動詞だけでなく、複数名詞、分詞由来の形容詞なども含む。
- 原形マップ内の語に加え、同じ原形のまま収録されている語も共通の辞書エントリを参照する。
- 熟語（`idioms`）は対象外とし、既存表示を維持する。

現行データを原形基準で集約すると、単語1,232スロットが1,183見出し語になり、48の見出し語が複数問題に登場する。原形マップ対象は260スロット・257原形である。

### 2-2. 日本語訳

- 活用形に合わせた訳ではなく、辞書的な訳へ統一する。
- 同じ原形に複数の収録済み語義がある場合は、一つの意味文字列へ統合する。
- 代表語義だけに絞らず、既存問題で扱っている意味を残す。

例:

| 出題形 | 原形 | 現在の意味 | 統一後の意味 |
| --- | --- | --- | --- |
| `implored` | `implore` | 懇願した | 懇願する |
| `averted` / `averting` | `avert` | 避けた、回避した / 回避する | 避ける、回避する |
| `provision` / `provisions` | `provision` | 条項、備え / 食料、備蓄 | 条項、備え；食料、備蓄 |
| `disappear` / `disappeared` | `disappear` | 消える、姿を消す / 消えた、見えなくなった | 消える、姿を消す |

### 2-3. 音声とIPA

- 暗記カードと意味4択では原形のIPAを表示する。
- 音声ボタンは原形専用MP3を再生する。
- 同じ原形の音声は一つだけ生成する。
- 既存の出題形音声は削除しない。

### 2-4. 学習単位と進捗

- 表示、意味、IPA、音声だけを原形単位で統一する。
- 同じ原形が別の問題に登場した場合も、問題ごとの学習スロットは維持する。
- 進捗キー、復習間隔、学習語数、回答履歴は統合しない。
- 既存利用者向けの進捗移行は行わない。

## 3. 変更しない範囲

- `data/vocab_*.json` の `word`、`meaning`、`ipa`。
- `data/questions_*.json` の問題文、選択肢、正解。
- 本番形式の英文穴埋め問題に表示する出題形。
- `surfaceOf()`、`itemKeyOf()`、既存の `vocabularyAudioPath()` の契約。
- localStorage・クラウドの進捗キー。
- 回答履歴に保存する出題形。
- 既存の出題形MP3。
- 熟語の表示、意味、音声。

## 4. データ設計

既存の `data/lemmas.json` を、出題形から原形への変換表と、原形単位の辞書エントリを持つ正本へ拡張する。

```json
{
  "meta": {
    "schemaVersion": 2,
    "note": "暗記カード・意味4択用の原形辞書。進捗キーと本番形式問題には使わない。"
  },
  "lemmas": {
    "provisions": "provision",
    "disappeared": "disappear"
  },
  "entries": {
    "provision": {
      "meaning": "条項、備え；食料、備蓄",
      "ipa": "/prəˈvɪʒən/",
      "audio": "assets/audio/lemma/provision.mp3",
      "surfaces": ["provision", "provisions"]
    }
  }
}
```

### 4-1. `lemmas`

- キーは出題形を小文字化した値。
- 値は原形・単数形。
- 原形と同じ語は登録しない。
- 既存マップを維持し、進捗や本番データには適用しない。

### 4-2. `entries`

- キーは原形・単数形。
- 原形マップの全値に対応するエントリを必須とする。
- `meaning` は収録済み語義を統合した辞書的意味。
- `ipa` と `audio` は原形用。
- `surfaces` は監査用に、そのエントリへ集約した既存出題形を保持する。
- 原形のまま収録されている同一語も `surfaces` に含める。

## 5. 実装手順

### Phase 0: 現行状態の固定

1. `git status --short` で既存変更を確認する。
2. `npm test` を実行し、実装前の基準を記録する。
3. `data/lemmas.json`、`static/mode-q1.js`、音声生成スクリプト、既存テストの現行契約を確認する。
4. Graftが新鮮なら影響範囲確認に使い、staleなら実コードを正とする。

### Phase 1: 辞書エントリ候補の生成

再実行可能な監査スクリプトを `scripts/` に追加する。

1. 全 `data/vocab_*.json` の `words` を走査する。
2. `surface -> lemma` を解決する。
3. 原形ごとに出題形、意味、品詞、IPA、出典ファイルを集約する。
4. 原形マップ対象257件について、編集・確認用一覧を生成する。
5. 次の項目を要確認として出力する。
   - 同じ原形に異なる意味がある。
   - 品詞が複数ある。
   - 原形化により受動・形容詞的意味が変わる。
   - IPA候補が複数ある、または取得できない。

候補生成は機械化するが、意味の確定は人手で行う。接尾辞や日本語の時制表現だけによる自動変換は正本にしない。

### Phase 2: 辞書的意味のキュレーション

1. 原形ごとに既存の語義を確認する。
2. 過去形・受動形の訳を辞書形へ直す。
3. 複数名詞を単数形の見出しで成立する訳へ直す。
4. 異なる語義を `；` などで統合し、既存問題の学習範囲を残す。
5. 別の見出し語と意味文字列が完全一致する場合は、意味4択で重複正解にならないか確認する。
6. 257件すべてに判断済みの印を付ける。

### Phase 3: 原形IPAと音声の生成

1. 原形用IPAを取得・確認する。既存の `scripts/enrich_flashcard_fields.py` のCMU辞書変換ロジックを再利用できるか先に確認する。
2. 原形音声用の生成スクリプトを追加する。既存の `scripts/generate_tts_1.py` と同じ音声設定・資格情報の扱いを踏襲する。
3. 出力先を `assets/audio/lemma/` とする。
4. 既存の `audioSlug()` と互換のファイル名規則を使う。
5. 原形ごとに一つのMP3だけ生成する。
6. dry-runで対象数とパス衝突を確認してから生成する。
7. 全エントリのMP3存在、非空ファイル、パス一意性を検証する。

### Phase 4: 共通解決関数の追加

`static/mode-q1.js` に学習表示専用の小さな解決関数を追加する。

想定する責務:

```js
canonicalHeadwordOf(item)
learningEntryOf(item)
learningMeaningOf(item)
lemmaAudioPathOf(item)
```

- `canonicalHeadwordOf()` は `word` 項目だけ原形マップを参照する。
- `learningEntryOf()` は原形の辞書エントリを返す。
- 辞書エントリがなければ既存の `word`、`meaning`、`ipa`、音声へフォールバックする。
- `surfaceOf()` と `itemKeyOf()` は変更しない。
- 原形解決を進捗保存や本番形式問題へ漏らさない。

### Phase 5: 暗記カードの統一

`buildFlashCard()` を辞書エントリ基準へ変更する。

```text
provision        /prəˈvɪʒən/  [音声]
出題形 provisions
名詞

意味
条項、備え；食料、備蓄
```

- 主見出しは原形。
- IPAと音声は原形用。
- 意味は統合した辞書的意味。
- 出題形は本番問題との対応を残すため補助表示する。
- 出題形のIPA・音声は暗記領域では使わない。
- 原形と出題形が同じ場合は出題形行を表示しない。
- 既存の語源、例文、関連情報、ナビゲーションは維持する。

### Phase 6: 意味4択の統一

`renderCheck()`、`meaningPoolForItems()`、`meaningDistractors()` と意味プールの構築箇所を辞書エントリ基準へ変更する。

- 問題語は原形を表示する。
- IPAを表示する場合は原形用を使う。
- 音声ボタンは原形MP3を再生する。
- 正解は `learningMeaningOf(item)` とする。
- 誤答候補も各項目の辞書的意味から作る。
- 正解と同じ意味文字列、候補間で重複する意味文字列を除外する。
- 候補不足時の既存フォールバック順は維持する。
- 正誤、解答時間、復習間隔、誤答回数、問題スロットは既存の `item` に対して記録する。
- 本番形式の4択問題と、その問題固有の選択肢は変更しない。

## 6. テスト計画

### 6-1. データ契約テスト

`scripts/check-lemma-headword.cjs` を拡張する。

1. `data/lemmas.json` がパースできる。
2. `lemmas` と `entries` がオブジェクトである。
3. 原形マップの全値に辞書エントリが存在する。
4. `meaning`、`ipa`、`audio`、`surfaces` が契約を満たす。
5. `surfaces` の全項目が実際の `vocab_*.json` に存在する。
6. 同じ原形に属する全出題形が同一エントリを参照する。
7. 全音声ファイルが存在し、音声パスが衝突しない。
8. 辞書エントリ数とキュレーション済み件数が一致する。

### 6-2. 実装境界テスト

1. `buildFlashCard()` が原形見出し、辞書的意味、原形IPA、原形音声を使う。
2. `renderCheck()` が原形見出しと辞書的意味を使う。
3. 意味候補プールが辞書的意味を使う。
4. 同一の意味文字列が4択へ重複しない。
5. `surfaceOf()`、`itemKeyOf()`、既存 `vocabularyAudioPath()` が原形辞書を参照しない。
6. 本番形式問題の選択肢が原形化されない。
7. 辞書エントリがない語と熟語が既存動作へフォールバックする。

### 6-3. 回帰テスト

- `npm test`
- `data/vocab_*.json` に意図しない差分がないことの確認。
- 問題数、語句スロット数、進捗キー生成結果が実装前と一致することの確認。
- 既存localStorageを読み込んでも学習済み状態が維持されることの確認。

### 6-4. 実ブラウザ確認

代表項目:

- 動詞: `implored -> implore`
- 複数名詞: `provisions -> provision`
- 分詞由来: `invigorated -> invigorate`
- 複数出題形: `averted` / `averting -> avert`
- 原形のまま収録された同一語: `provision`
- 辞書エントリがない語。
- 熟語。

確認内容:

- 暗記カードの見出し、意味、IPA、音声。
- 意味4択の見出し、正解、誤答候補、音声。
- 誤答後の復習カード。
- キーボード操作。
- 狭い画面と通常幅。
- コンソールエラーと音声404がない。

## 7. 実装ゲート

### Gate A: 代表5語

次のような異なる型を含む5語だけで、データ形式と表示を試作する。

- 通常の過去形動詞。
- 複数名詞。
- 分詞由来の形容詞。
- 複数出題形を持つ原形。
- 複数語義を統合する原形。

暗記カード、意味4択、音声、既存進捗をブラウザで確認し、辞書エントリの粒度を確定する。

### Gate B: 全257原形

Gate A承認後に全エントリを整備し、自動検証と目視監査を行う。機械生成結果を未確認のまま正本へ入れない。

## 10. レビュー後の修正計画

追加日: 2026-08-26
状態: 公開済み（2026-08-26）

実装レビューでは、原形表示と意味4択の基本経路は動作した。一方で、原形音声の未生成、Pages公開経路の不足、統合語義の欠落、原形品詞の誤りが確認された。以下の順序で修正し、受入条件を満たす。

### 10-1. 音声欠落をテスト失敗にする

対象:

- `scripts/check-lemma-headword.cjs`

修正内容:

1. 原形MP3が1件でも存在しない、または0バイトなら通常テストを失敗させる。
2. 現在の `pending` 警告だけで成功する処理を廃止する。
3. 音声生成前のデータ確認が必要な場合は、通常テストとは分離した明示的なオプションを用意する。
4. `npm test` では欠落許可オプションを使わず、音声の完全性を必須とする。

確認手順:

1. 原形音声がない状態で `npm test` が失敗することを確認する。
2. 257件すべての音声生成後にだけ成功することを確認する。

### 10-2. 辞書的意味を全257原形で再監査する

対象:

- `scripts/build_lemma_entries.py`
- `data/lemmas.json`

修正内容:

1. 原形ごとに、すべての出題形、元の日本語訳、統合後の日本語訳、出典ファイルを一覧化する監査処理を追加する。
2. 元の語義が統合後に含まれていない可能性がある項目を警告する。
3. 警告項目を人手で確認し、`MEANING_OVERRIDES` を修正する。
4. 全257原形について確認済みであることを記録する。
5. 統合後の意味が別見出し語と重複し、意味4択で複数正解にならないか確認する。
6. 全279件の元語義と統合後語義を結び付けたレビュー用ハッシュを保存し、どちらかが変わった場合は再確認まで生成とテストを失敗させる。

最初に修正する既知項目:

| 原形 | 現在の統合後の意味 | 既存データで欠落している意味 | 修正候補 |
| --- | --- | --- | --- |
| `liaison` | 連絡、協力関係 | 密通 | 連絡、連携、協力関係；密通 |
| `scamper` | 走り回る、ちょこちょこ走る | 走り去る | 走り回る、ちょこちょこ走る、走り去る |

監査スクリプトは各元語義に `retained` または `merged-as-dictionary-form` の扱いと統合先を出力する。最終的な意味の確定は人手で行い、確認済みスナップショットのハッシュが一致する場合だけ `reviewed` とする。文字列の部分一致だけで語義の保持を合格にしない。

### 10-3. 原形の品詞を監査・修正する

対象:

- `scripts/build_lemma_entries.py`
- `data/lemmas.json`

修正内容:

1. 接尾辞だけによる品詞補正を補助扱いにする。
2. 原形単位のレビュー済み品詞上書き表を追加する。
3. 全257原形について、辞書見出しとしての品詞を確認する。
4. 複数品詞を統合する場合の表記順と区切りを固定する。
5. 再生成後もレビュー済み品詞が失われないようにする。

最初に修正する既知項目:

| 原形 | 現在 | 修正後 |
| --- | --- | --- |
| `deify` | 名詞 | 動詞 |
| `incarcerate` | 名詞 | 動詞 |

テストには、上記2語と複数品詞の代表例を固定ケースとして追加する。

### 10-4. 原形音声を全件生成する

対象:

- `scripts/generate_lemma_tts.py`
- `assets/audio/lemma/`

手順:

1. dry-runで257件の原形と出力パスを確認する。
2. Azure Speechで原形ごとに一つのMP3を生成する。
3. 257件すべてが存在し、0バイトでなく、ファイル名が衝突していないことを自動確認する。
4. `data/lemmas.json` の `audio` と実ファイルの対応を確認する。
5. 代表語を実際に再生し、出題形ではなく原形が読まれていることを確認する。

代表確認語:

- `equivocate`
- `implore`
- `provision`
- `deify`
- `incarcerate`

生成途中で失敗した場合に、生成済みMP3を再利用して再開できる現在の挙動は維持する。APIキーなどの資格情報は環境変数だけで扱う。

### 10-5. Pages公開物へ原形音声を含める

対象:

- `.github/workflows/pages.yml`

修正内容:

```sh
mkdir -p _site/assets/audio/vocab _site/assets/audio/lemma
cp -R assets/audio/vocab/* _site/assets/audio/vocab/
cp -R assets/audio/lemma/* _site/assets/audio/lemma/
```

追加検証:

1. Pages準備処理が `assets/audio/lemma` を含むことを静的テストで確認する。
2. `_site/assets/audio/lemma` のファイル数が辞書エントリ数と一致することをCI内で確認する。
3. 代表MP3が公開成果物に含まれることを確認する。
4. 公開を依頼された場合は、公開URL上で代表MP3がHTTP 200になることを確認する。

### 10-6. 計画書と実装状態を同期する

本修正の完了時に、この文書冒頭の状態と各ゲートを実際の結果へ更新する。

- `未実装`
- `修正中`
- `実装済み・未公開`
- `公開済み`

実装と公開は別の状態として記録し、音声未生成やテスト未確認の状態を `実装済み` としない。

### 10-7. 修正後の検証順序

1. 音声未生成状態で `npm test` が意図どおり失敗する。
2. `scripts/build_lemma_entries.py --dry-run` を実行する。
3. 全257原形の意味と品詞を監査する。
4. 原形音声257件を生成する。
5. `npm test` を実行する。
6. Pages成果物をローカルで組み立て、原形音声257件が含まれることを確認する。
7. 実ブラウザで暗記カードと意味4択を確認する。
8. コンソールエラー、音声404、ブラウザ読み上げへの意図しない退避がないことを確認する。
