## 1. グルーピングの再実装（症状A・B）

`scripts/build_topic_data.py` の `choose_groups` を、axis 先行からトピック先行に変える。

1. セット内をトピック単位に分ける。
2. **各トピック内で4件の組を作る**。条件は現行と同じ「グループ内にちょうど1件だけの axis が存在する（その語が正答）／同一 axis は2件まで／意味の重複なし」。トピックの語数 n に対し `floor(n/4)` 問を目標とし、組合せ探索で解く（n は最大17なので全探索で足りる）。
3. トピックごとの端数（0〜3件）をセット単位のプールにまとめ、**混在問**を作る。混在問も同じ axis 規則を満たすこと。
4. 4の倍数に足りない分だけ既出語を再掲する。再掲は**候補語が複数ある axis から選び、同じ語の再掲は1回まで**（1語が3問以上に出ることを禁止）。
5. 上記を満たす解が作れない場合はエラーで落とす（黙って条件を緩めない）。

### 目標値
- 同一トピックの問: **55問以上**（試算では61問まで可能。現状18問）
- 1語が登場する問数: **最大2問**（現状は最大4問）
- 総問数84問・語句324件は変更しない

### レポート出力
ビルド時に「トピックごとの問数・端数」「同一トピック問の総数」「再掲した語」を標準出力に出す。axis タグの偏りが原因で組めないトピック（例: 戦争と紛争は12語中10語が `problem` で1問しか作れない）を可視化し、後追いのタグ見直し判断に使う。

## 3. 設問文の作り直し（症状C含む）

`data/topic_question_stems_1.json` は正答キー（`topic::en`）で引く形なので、**再グルーピング後も正答が変わらなかった問の設問文はそのまま使える**。`load_stems` がキー不一致で `missing` / `extra` を列挙するので、その差分が書くべき本数になる。

作成基準（[TOPIC_QUESTION_STEMS_PLAN.md](TOPIC_QUESTION_STEMS_PLAN.md) §6 から変更なし、和訳の条件だけ追加）:

- **英文**: 20〜40語・1〜3文。空所の前後に正答だけが成立する根拠（因果・増減・共起語・対比）を置く。語句の例文とは別の場面にする。
- **和訳**: 空所記号を使わず**全訳**にする。正答の意味を訳文に織り込む。
  ```
  誤: 高齢者の（　）が明らかになったため、その町は地域巡回バスと…
  正: 高齢化社会の進行が明らかになったため、その町は地域巡回バスと…
  ```
- **一意性**: 同一トピックの誤答が並ぶぶん、手がかりの作り込みが今までより重要になる。`scripts/review_topic_questions.py` の4通り比較で毎問確認する（完了条件）。

## 4. 検証の追加（`scripts/check_q1_data.py`）

既存の検証（stem の空所1つ／正答が stem に出ない／stem 15語以上／stem 骨格が語句例文と一致しない／stem 骨格の全体一意／例文・訳の骨格一意／正答と誤答の axis 不一致）はそのまま残し、以下を追加する。

1. **必須**: 設問文訳に空所記号（`( )` / `（　）` / 中身が空白のみの括弧）を含まないこと。
2. **必須**: 同一セット内で同じ語が3問以上に登場しないこと（症状Bの再発防止）。
3. **警告**（エラーにしない）: 設問文訳に正答の `meaning` が含まれない設問を一覧表示する。言い換えを許すため落とさないが、訳し漏れの検知に使う。
4. **警告**: 同一トピックで揃っていない問の数を表示する。
