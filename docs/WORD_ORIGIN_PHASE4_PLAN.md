# 単語語源 段階4: 仲間語パネルを級横断にする

対象: `static/mode-q1.js` / `data/word_origins.json` / `scripts/check-word-origin-data.cjs` / `scripts/check-word-origin-ui.cjs` / `docs/WORD_ORIGIN_AUTHORING.md`
関連: [WORD_ORIGIN_PLAN.md](WORD_ORIGIN_PLAN.md)（全体）/ [WORD_ORIGIN_PHASE3_PLAN.md](WORD_ORIGIN_PHASE3_PLAN.md)（語根の第2波）
前提: 段階3＝`deb05fc`（語根33個・A型136語・B型18語）
状態: 未着手

## 0. なぜデータではなく表示側を直すのか

段階3の打ち切り基準（1語根あたりの真の候補が3語未満）に、`val` と `tang` が既に到達した。語根を増やす第3波は1語根あたり2〜3語しか採れず、収穫が見合わない。

一方で、**すでに入れた136語が学習者に届いていない**ことが測定で分かった。

| 測定項目 | 実測 |
| --- | --- |
| A型カード×級 の組み合わせ | 138 |
| **同じ級に仲間語が1語も無く、パネルが出ないもの** | **56（41%）** |
| 同じ級だと仲間語が減るもの | 71 |
| 3枠のうち語幹変異形（`inherent`/`inherently` 型）が占める割合 | 18/358（5%） |

仲間語は `pooledData(currentGrade())` から集めるため、**級をまたいだ語根の仲間が見えない**。例:

- `composer`（準1級）… `pos` の仲間語は全体で9語あるが、準1級には0語 → **パネルごと非表示**
- `defer`（1級）… `fer` は全体4語だが、1級には0語 → 非表示
- `illustrate`（2級）… `luc` は全体5語だが、2級には0語 → 非表示

語根は級をまたいで共通なのだから、**準2級の `transfer` が1級の `defer` の仲間として出るのはむしろ望ましい**（易しい既知語で語根が補強される）。段階4はここを直す。語源データの追加はしない。

## 1. 修正1: 仲間語を語源データだけで組み立てる（級の壁を外す）

### 現状の作り

`wordOriginSiblingItems()` は**語彙アイテム（`vocab_*.json` 由来のオブジェクト）**を集める。訳は `item.meaning` から取るため、その語が読み込み済みのデータセットか、同じ級のプールに無いと仲間語にできない。

### 変更

`data/word_origins.json` の各エントリに、**表示用の短い訳 `gloss` を持たせる**。仲間語は語彙アイテムではなく `word_origins.json` から直接組み立てる。

```json
"transfer": {
  "type": "A",
  "root": "fer",
  "gloss": "異動させる",
  "parts": [ … ],
  "derivation": "越えて運ぶ → 異動させた"
}
```

- 級・データセットへの依存が消え、`pooledData` の読み込み状況にも左右されなくなる（段階0から残っていた「ホーム描画のタイミング次第でパネルの有無が変わる」問題も同時に解消する）。
- `meaning` をそのまま使うと「食料、備蓄；条項、備え」のように長いものがあるため、**パネル用に短く切れる**利点もある。
- 重複は検査で縛る（下記）。

### 代替案（採らない）

`scripts/` で `root → [{lemma, gloss}]` の索引ファイルを生成する案もあるが、ファイルと生成手順が1つ増える。136語のうち仲間語に出るのはA型だけで、`word_origins.json` に1フィールド足すほうが小さい。

### 並べ替え

仲間語の候補は次の優先順で並べ、既存の `_wordOriginSlot` によるローテーションはそのまま使う（決定的・乱数なし）。

1. **いま学習中のデータセットに含まれる語**（今までどおり手元の語を優先）
2. 語幹が異なる語（修正2）
3. それ以外（他級の語・語幹変異形）

表示は最大3語のまま。

## 2. 修正2: 語幹変異形を後回しにする

`inherent` の仲間語が `inherently`、`cordial` の仲間語が `cordially` だけになると、語根の広がりが伝わらない。ただし影響は**3枠のうち5%**なので、**除外ではなく後回し**にとどめる（`vid` の `provision`/`proviso` のように、変異形しか無い語根では出さないと0語になる）。

判定は次の単純規則にする。語源学的な判定はしない。

```js
function sameStem(a, b) {
  return a.startsWith(b) || b.startsWith(a) || a.slice(0, 5) === b.slice(0, 5);
}
```

## 3. 検査

`check-word-origin-data.cjs`

- A型の `gloss` は必須・非空。
- `gloss` は、その原形の `vocab_*.json` の `meaning` のいずれかに**部分文字列として含まれる**こと。勝手な訳の創作を防ぎ、短縮だけを許す。
- `gloss` は**16文字以内**（パネルの1行に収める）。

`check-word-origin-ui.cjs`

- `wordOriginSiblingItems`（改名するなら新しい名前）が `wordOriginMap` を参照し、`pooledData` に依存しないこと。
- 並べ替えに `sameStem` を使い、`Math.random` を使わないこと。
- 既存の「進捗キー・音声・選択肢に語源データを流さない」検査はそのまま維持する。

## 4. 影響範囲

- `data/word_origins.json`: A型136語に `gloss` を追加（B型は仲間語に出ないので不要）。
- `static/mode-q1.js`: `wordOriginSiblingItems` の書き換えと並べ替え。`flashWordOrigin` の表示側は `sibling.gloss` を読むだけの変更。
- `pooledData` そのものは意味復習で使い続けるため、削除しない。
- CSSの変更なし。`index.html` の `?v=` は上げる（JSとデータの両方が変わるため）。

## 5. 手順

1. 検査（3章）を先に入れる。`gloss` 未設定で落ちる状態にしてから埋める。
2. `data/word_origins.json` のA型136語に `gloss` を入れる。`vocab_*.json` の `meaning` の**先頭の語義だけ**を取るのが基本。
3. `mode-q1.js` を書き換える。
4. `npm test`。
5. 実ブラウザで確認する。
   - `composer`（準1級）… `pos` の仲間語が3語出る（今は非表示）
   - `defer`（1級）… `fer` の仲間語が出る
   - `inherent`（1級）… 先頭が `inherently` ではなくなる
   - 375px幅、コンソールエラー0
6. `index.html` の `?v=` を上げて1コミット。

## 6. 合格条件

- A型のカードで、**同じ級に仲間語が無くてもパネルが出る**（56カードが対象）。
- 語幹変異形しか無い `vid` では、これまでどおり `proviso` が出る（後回しであって除外ではない）。
- `npm test` が通り、`gloss` がすべて `meaning` の部分文字列である。
- 意味練習・音声・進捗の挙動が変わらない。

## 7. 非目標

- 語源データの追加（語根の第3波はやらない。0章の打ち切り基準に従う）。
- 仲間語に級バッジを付けること。易しい語が混ざるのは利点であって、区別する必要はない。
- 熟語側（`coreImage`）の仲間例を級横断にすること。熟語は語根のような共通軸が無いため、別問題として扱う。
