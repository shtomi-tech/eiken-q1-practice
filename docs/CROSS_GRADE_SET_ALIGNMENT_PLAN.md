# 英検各級セットの1級基準整合 実装計画

状態: 既存セット整合完了（新規セット拡充は段階5の承認待ち）

## 1. 目的

`eiken1-mock-6` を品質の参照実装とし、英検5級・準2級・2級・準1級の既存セットを、
各級の公式形式と既存進捗を保ったまま同じ完成条件へ揃える。

ここで揃えるのは問題内容や件数そのものではなく、次の品質である。

- 4択と正答の一意性、問題文訳、選択肢と語彙項目の対応
- 意味、品詞、例文、例文訳、IPA、語源または除外理由
- 熟語の核心イメージ
- 出題形と原形の表示・音声
- 出典、生成元、検査、独立レビュー、公開確認

## 2. 固定する互換性

- 公式過去問の設問数・選択肢・正答位置・出典を変更しない。
- `datasetId`、設問番号、`itemKey`、進捗キー、保存キー、公開URLを変更しない。
- 別級へ1級の25問 / 100語句、84語 / 16熟語を適用しない。
- `questions_*.json` / `vocab_*.json` は生成物として扱い、正本または再適用スクリプトから更新する。
- IUHWセットと非公開のテーマ別データは今回の整合対象に含めない。
- 新しい公式問題や自作模試の追加は、既存セット整合が完了してから1セットずつ行う。

## 4. 実装方針

### 段階0: ベースラインを固定する

1. `git status --short` で既存変更を確認する。
2. `data/manifest.json` から対象IDと実件数を取得し、固定値を手で転記しない。
3. 次を実行し、開始時点の結果を整合文書へ記録する。

```powershell
py -3 scripts/check_q1_data.py
py -3 scripts/check_p2_mock_data.py
py -3 scripts/check_5_data.py
py -3 scripts/check_mock_6_data.py
npm test
```

4. `check_eiken1_alignment.py --audit` を対応25セットへ実行し、0件であることを確認する。

### 段階1: 全級共通の整合検査へ改める

対象:

- `scripts/check_eiken1_alignment.py`
- `scripts/check_5_data.py`
- `scripts/check_q1_data.py`
- `README.md`

実装:

1. `check_eiken1_alignment.py` に `eiken5` を追加し、級別ポリシーを1か所へ集約する。
2. `--all` を追加し、manifest上の英検セットだけを一括検査できるようにする。
3. 全級で次を検査する。
   - manifestと実データの件数一致
   - 4択、空所1件、正答1件、設問番号の連続
   - 問題文訳、意味、品詞、例文、例文訳、単語IPA
   - 例文8語以上、見出し語句1回、例文骨格の重複なし
   - 単語の語源または明示的な除外理由
   - `coreImage` を持つ項目のA/B/C型契約
   - 表層MP3と、原形表示対象の原形MP3
4. 5級Q15の `is studying` / `are studying` / `am studying` は、公式選択肢と進捗キーを
   保つため `word` のまま扱う。語源を持たない文法形式として明示的な除外理由を正本へ記録する。
5. `check_5_data.py` は公式選択肢・正答照合の専用検査として残し、共通検査と役割を分ける。
6. 既存のコマンド名は互換性のため残す。名称変更を行う場合もラッパーを残す。

受入条件:

- 初回の `--all --audit` で、意図した音声不足、準1級核心イメージ不足、5級Q15の
  語源除外理由不足だけが検出される。
- 整備後の通常モードで全英検セットが0件になる。
- 既存の公式問題・正答・IDに差分がない。

### 段階2: 準1級の句動詞へ核心イメージを追加する

対象:

- `scripts/q1_pre1_metadata.py`
- `scripts/curate_pre1_data.py`
- `data/vocab_pre1_2025-2.json`
- `data/vocab_pre1_2025-3.json`
- `data/vocab_pre1_2026-1.json`
- `static/src/90-learn-flow.js`
- `scripts/check-core-image-data.cjs`
- `scripts/check-core-image-ui.cjs`
- `docs/EIKENP1_ALIGNMENT.md`

互換方式:

- 48件は `type: "word"` と `word` フィールドのまま保持する。
- 各項目へ `coreImage` だけを追加する。`itemKeyOf()` が生成する `word:<surface>` は変えない。
- 暗記カードは `item.coreImage` があれば型に関係なく核心イメージを優先表示し、なければ従来どおり単語語源を表示する。
- 意味チェックのダミー選択肢プールも `word` のまま保持する。

作業順:

1. 1回分16件ずつ、`CORE_IMAGE_AUTHORING.md` に従ってA/B/C型を判断する。
2. A/B型は個別の `chain` を作成し、A型だけ `particle` / `particleSense` を付ける。
3. C型は無理に連鎖を作らず、正本の `cReasons` に理由を残す。
4. `q1_pre1_metadata.py` を正本としてJSONへ再適用する。
5. `check-core-image-data.cjs` を、`idioms`だけでなく `coreImage` を持つ互換項目も検査できるようにする。
6. 2025-2、2025-3、2026-1を別々に検証する。

受入条件:

- 変更前後で各JSONの問題文、選択肢、正答位置、`word`、`type`、`itemKey`が同一。
- 既存の `word:<surface>` 進捗を用意したブラウザで、学習済み状態が維持される。
- 対象句動詞の暗記カードに核心イメージが表示される。
- 単語カードの語源表示と熟語カードの既存表示に回帰がない。

### 段階3: 5級と準2級模試の表層MP3を揃える

対象:

- `assets/audio/vocab/5/2026-1/`
- `assets/audio/vocab/pre2/mock-{1,2,3,4}/`
- `scripts/check_eiken1_alignment.py`
- `README.md`

作業順:

1. Azureキーをログ・ファイル・チャットへ出さず、環境変数だけで設定する。
2. 最初に `--dry-run` で対象件数と出力先を確認する。
3. 5級60件、準2級模試は1回60件ずつ生成する。

```powershell
py -3 scripts/generate_tts_1.py --grade 5 --round 2026-1 --dry-run
py -3 scripts/generate_tts_1.py --grade pre2 --round mock-1 --dry-run
```

4. 各セットで0バイト、欠番、重複slug、単語/熟語ディレクトリの誤りを検査する。
5. 音声が揃ったセットから共通検査の必須対象へ切り替える。

受入条件:

- 5級60/60件、準2級模試240/240件のMP3が存在し、すべて0バイトより大きい。
- 暗記カードと意味チェックで、404を経由せずMP3が再生される。
- 原形表示対象は原形MP3を使い、表層MP3を原形音声として流用しない。

### 段階4: 下位級公式セットの再生成経路を閉じる

対象:

- 2級公式3回
- 準2級公式3回
- 準1級公式3回
- 関連ビルド・metadata・curateスクリプト

実装:

1. 各級について「原本取得・抽出」と「教材メタデータ適用」を分ける。
2. 公式PDFは `data/eiken_<grade>/<round>/` のgitignore対象へ置き、公開・コミットしない。
3. 1級公式セットと同じく、問題PDF・解答PDFから設問、選択肢、正答位置を再生成できる入口を用意する。
4. 既存の `q1_eiken2_metadata.py`、`q1_eikenp2_metadata.py`、`q1_pre1_metadata.py` は、例文・訳・出典・正答フラグ等の正本として再利用する。
5. 再生成前後を意味的に比較し、問題文、選択肢、正答位置、語句表層が一致しなければ生成を失敗させる。
6. 原本がない回は推測で補わず、未再生成として明記して止める。

受入条件:

- 新しいチェックアウトでも、原本PDFを所定位置へ置けば各公式セットを再生成できる。
- PDFを除く生成手順と必要ファイルがREADMEに記載される。
- 原本PDFがgit管理・Pages成果物へ混入しない。

### 段階5: 独立レビューと文書を揃える

対象:

- `docs/EIKEN2_ALIGNMENT.md`
- `docs/EIKENP2_ALIGNMENT.md`
- `docs/EIKENP1_ALIGNMENT.md`
- 必要なら級別のレビュー補助出力

実装:

1. 2級、準2級公式、準1級の設問文と4択だけを、正答キーを伏せて別モデルへ渡す。
2. 各設問について成立する選択肢を列挙し、複数成立・不成立・不自然さを記録する。
3. 公式問題は勝手に修正せず、公式解答との関係を注記する。教材側の訳や例文だけを直す場合も正本へ反映する。
4. 使用モデル、対象セット、レビュー日、判定、要確認事項を各整合文書へ残す。
5. `EIKENP1_ALIGNMENT.md` の「MP3未生成」という古い記述を、実ファイル確認結果へ更新する。

受入条件:

- 対象9公式セットの全設問にレビュー結果がある。
- 自作教材部分を修正した場合、生成・共通検査・再レビューをやり直している。
- 文書の件数・音声状態が実データと一致する。

## 6. 検証

### 機械検査

```powershell
py -3 scripts/check_q1_data.py
py -3 scripts/check_eiken1_alignment.py --all
py -3 scripts/check_5_data.py
py -3 scripts/check_p2_mock_data.py
py -3 scripts/check_mock_6_data.py
npm run build
npm test
```

データを再生成したセットは、対象のビルドスクリプト実行後に
`enrich_flashcard_fields.py --file <対象vocab>` を実行し、対象外JSONが変わっていないことを確認する。

### 実ブラウザ

`py -3 -m http.server 8061 --bind 127.0.0.1` で起動し、`?g=5`、`?g=pre2`、`?g=2`、
`?g=pre1`、`?g=1` をそれぞれ確認する。

- ホームのセット数・件数・復習上限
- 暗記カード → 意味チェック → 本番形式4択 → 最終チェック
- 準1級句動詞の核心イメージ
- 単語語源と既存熟語の表示
- MP3再生、原形音声、音声エラーなし
- 既存進捗の復元、別級進捗の非表示と保持
- 375px相当とデスクトップ幅、キーボード操作、コンソールエラー

### 差分検査

- `git diff -- data/questions_*.json` で公式設問の意図しない変更がない。
- 対象セットごとに問題文、選択肢、正答位置、表層語句、IDの比較結果を残す。
- `static/src/*.js` を変更した場合だけ `npm run build` で `static/mode-q1.js` を再生成し、
  `index.html` の該当キャッシュバスターを更新する。

## 7. 実施単位とコミット境界

実装する場合は次の単位を混ぜない。

1. 共通検査の拡張
2. 準1級の表示互換コードと検査
3. 準1級2025-2、2025-3、2026-1（各セット個別）
4. 5級音声
5. 準2級模試音声（各セット個別）
6. 公式セット再生成経路（級ごと）
7. 独立レビュー記録とREADME整合
8. 新規セット（常に1セット1コミット）

push・デプロイは別途依頼された場合だけ行う。デプロイ時はActions成功だけでなく、公開URLの
manifest、対象JSON、JS/CSS、MP3を直接確認する。
