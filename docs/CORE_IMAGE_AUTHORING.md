# 熟語カード「核心イメージ」作成基準

熟語の暗記カードに出る核心イメージ（連鎖）を書くときの**正本**。
新しい問題セットを追加するとき、既存セットへ熟語を足すときは、このファイルに従う。

- 機械で判定できる規則は `scripts/check-core-image-data.cjs` が強制する（`npm test` で実行）。
- このファイルは、その検査に加えて**人が判断する部分**を定める。
- 経緯は `CORE_IMAGE_PLAN.md` / `CORE_IMAGE_SENSE_PLAN.md` / `CORE_IMAGE_ROLLOUT_PLAN.md` と各 `*_FIX_PLAN.md` にあるが、**運用時に読むのはこのファイルだけでよい**。

## 1. まず型を決める

熟語をA・B・Cのどれかに分類する。**全部にAを当てはめない。**

| 型 | 判定 | 付けるもの | 例 |
| --- | --- | --- | --- |
| A | 動詞＋不変化詞（句動詞） | `chain` ＋ `particle` ＋ `particleSense` | `patch up` `crack down` `branch off` |
| B | 前置詞句・定型表現で、構成語から意味を導ける | `chain` のみ（`particle` なし） | `in search of` `as long as` `for the time being` |
| C | 連鎖がこじつけになるもの | **何も付けない** | `provided that` `shake hands` `more or less` |

**C の扱い**: `coreImage` を付けず、`check-core-image-data.cjs` の `cReasons` に phrase と理由を1行追記する。理由が無いと検査で落ちる。逆に `cReasons` にある熟語へ `coreImage` を付けても落ちる。**件数を消化することが目的ではない**ので、迷ったらCにして理由を書く。

Cの典型:
- 接続詞句（`provided that` `rather than` `even though`）
- 動詞＋名詞の定型表現（`shake hands` `make sense` `take a nap`）
- 等位・反復の定型表現（`more or less` `bit by bit` `safe and sound`）

## 2. 連鎖（`chain`）の書き方

### 形

```
構成語 → 不変化詞 → （必要なら派生義） → 中心義
```

```json
"chain": [
  { "term": "patch", "gloss": "つぎを当てて直す" },
  { "term": "up",    "gloss": "整った状態まで" },
  { "gloss": "整った状態まで仕上げる" }
]
```

- **2〜5段**。A型は不変化詞ステップが必須なので実質3〜5段になる。
- **最後の要素に `term` を付けない**。最後は導出結果（中心義）。
- `term` は**小文字の原形**で書く。`phrase` が活用形でも原形にする（`scraped together` → `scrape` / `together`）。`phrase` 自体は絶対に書き換えない（進捗キー・音声パスの元になるため）。
- 最後の `gloss` は、その熟語の `meaning` の中心義とそろえる。**方向語だけで終わらせない**（`buckle down` を「下へ」で終えない）。

### A型は不変化詞を必ず1ステップに立てる

`particle` を持つのに連鎖に不変化詞が無いと、データ上の分類と連鎖が一致しない。核心イメージの連鎖を成立させるため、検査で落ちる。

不変化詞ステップの `gloss` は、割り当てた `particleSense` の `label` を土台にし、その熟語の文脈へ短く言い換える。ラベルをそのまま貼らない。

| 熟語 | sense のラベル | 連鎖に書く gloss |
| --- | --- | --- |
| `patch up` | 完全に・し尽くして終える | 整った状態まで |
| `crack down` | 押さえつけて動きを止める | 下へ押さえつけて |
| `branch off` | 切り離す・遮断する | 本体から切り離して |

### 3語以上の熟語

**動詞の直後に不変化詞ステップを置く**。目的語（`it` `my mind` など）や後続の前置詞はステップにしない。

```
fill it out      → fill(満たす) → out(外へ作り出して) → 外へ内容を出して書き上げる
make up my mind  → make(作る)   → up(考えを組み上げて) → 考えを組み上げて決める
look forward to  → look(見る)   → forward(前方の出来事へ意識を向けて) → 前方の出来事を楽しみに待つ
```

### やってはいけないこと

- **循環**: 構成語の `gloss` に熟語の意味をそのまま書く（`eke out` の `eke` を「かろうじて得る」と書くなど）。構成語は構成語自身の意味を書く。
- **他動詞・自動詞の取り違え**: `waste away`（自動詞）の `waste` を「消耗させる」と書かない。
- **意味の限定しすぎ**: `hang out` を「外で」に限定しない（屋内でも使う）。

## 3. `particle` と `particleSense`

### `particle`

- `phrase` に実際に含まれる語であること（検査で照合する）。
- **末尾語から機械的に決めない**。`Snap out of` の核は `out`、`Stand up to` は `up to`。連鎖のどのステップが核かで判断する。
- `data/particle_images.json` に存在するキーであること。無ければ辞書に追加する（4章）。

### `particleSense`

- 参照する不変化詞が `senses` を持つなら**必須**。
- **`"general"` という id は作らない・使わない**（検査で落ちる）。意味の向きが逆の熟語が同じ束に入り、用法別にした意味が無くなる。
- 選び方は「**連鎖に書いたその不変化詞の `gloss` と一致する用法**」。`meaning` からではなく連鎖から選ぶ。
- 一致する用法が無ければ辞書に用法を足す（4章）。既存の用法に無理に押し込まない。

## 4. 不変化詞辞書（`data/particle_images.json`・検証用）

この辞書は熟語データの検査と作成補助に残す。共有イメージや仲間例を暗記カードへ表示する用途では使わない。

```json
"down": {
  "core": "下へ・押さえつける方向へ",
  "note": "動きや勢いを下げ、落ち着かせるイメージ",
  "siblings": [ … ],          // senses を持たない不変化詞のフォールバック（3〜6件）
  "senses": [
    { "id": "suppress", "label": "押さえつけて動きを止める", "siblings": [ … ] }
  ]
}
```

### 用法（`senses`）を割る基準

- **同一セット内に同じ不変化詞が複数出るとき**に割る。1〜2件しか出ない不変化詞は `siblings` だけでよい。
- **単発の用法を新規に増やさない**。参照が1件だけの用法は、既存の用法に統合できないか先に検討する。
- 用法数が増えすぎたら統合する（`out` は10以下を検査で強制）。

### 仲間例（`siblings`・検証用）

- 1つの用法につき**3〜6件**。表示は3件で、残りは重複回避のための余剰。
- **同一セット内で `n` 件がその用法を参照するなら `min(3 + (n-1), 6)` 件以上**必要（検査で強制）。
- **その熟語自身を入れない**（`stand up to` のカードに `stand up to` を出さない）。検査は `phrase` と連鎖の `term` 連結形の両方で照合する。
- 同一不変化詞の別用法に同じ phrase を重複させない。必要なら、その phrase を実際に参照している熟語の用法側にだけ残す。
- 英検1級レベルに寄せない。**用法のイメージが立つ平易な熟語**を選ぶ。
- 一般的でない句動詞を作らない（`hand up` のような形は不可。`hand over` / `hand in` が通例）。

### 表示の仕組み（把握しておくこと）

仲間例は暗記カードには表示しない。重複や用法の対応を検査するためのデータとして、同一不変化詞・用法の候補を3〜6件保つ。

## 5. `coreImage` に置けるキー

`chain` / `particle` / `particleSense` / `note` / `siblings` の5つだけ。それ以外は検査で落ちる。

- `note`: 連鎖だけで足りないときの1〜2文の補足。任意。
- `siblings`: 辞書に収まらない熟語のための例外上書き（1〜3件）。**常用しない。**
- `meaning` を書かない。UIは読まない。過去に、意味を `coreImage.meaning` に書いて連鎖が未完成なまま公開された事故がある。

## 6. 語義の判断

- 根拠は**既存の `meaning` と `example`**を第一とする。辞書の記述に合わせて `meaning` を書き換えない。
- 不確かな語義・訳・解釈は**断定しない**。連鎖が比喩の飛躍でしか成立しないものはC型にする。
- 公開済みの `gloss` を後から変えるときは最小限にする。学習者が既に見ているため、意味が変わらない言い換えのための書き換えはしない。
- 判断に迷って付けなかった熟語は、作業のたびに件数と理由を報告する。

## 7. 新しいセットを追加する手順

1. `data/manifest.json` にセットを登録する（配信対象の判定はここを見ている）。
2. 熟語をA・B・Cに分類する。C型は `cReasons` に理由を追記する。
3. A型に `chain` ＋ `particle` ＋ `particleSense` を書く。必要なら辞書へ用法を追加する。
4. B型に `chain` だけ書く。
5. `npm test` を通す。検査は**件数を固定していない**ので、セットを足しても総数で落ちることはない。落ちるのは契約違反だけ。
   - 新しいセットを `manifest.json` に登録した時点で、そのセットの熟語は**全件がA・B・Cのいずれかに分類済み**であることを要求される。未分類の熟語があると `〈phrase〉: coreImage を付けるか、付けない理由を … cReasons に追記してください` で落ちる。**登録とデータ作成は同じコミットにまとめる**のが安全。
6. `.github/workflows/pages.yml` の配信対象にデータファイルが含まれているか確認する。
7. 公開後、実ブラウザでそのセットの熟語カードを確認する。連鎖・例文が表示され、共有イメージと仲間例のパネルが表示されず、コンソールエラーが無いこと。

### 検査が出力する記録

`npm test` は次を出力する。付与状況の確認に使う。

```
particle chain coverage: <件数> entries; lengths {"3":…,"4":…}
core image delivery scope: <セット数> sets / <熟語数> idioms
core image progress: <ファイル名>: <熟語数> idioms / <付与数> coreImage
core image unique categories: particle-backed … / chain-only … / C …
```

## 8. 実装側の前提（変更するときは影響を確認する）

| 事項 | 場所 |
| --- | --- |
| 連鎖の描画 | `static/mode-q1.js` の `flashCoreImage()` |
| 不変化詞辞書・仲間例の検証 | `scripts/check-core-image-data.cjs` |
| 意味チェック直後の1行表示 | `appendCheckFeedback()`。連鎖の `gloss` を `→` で連結 |
| 語彙・問題JSONの取得 | `cache: "no-store"`。データだけ更新してもリロードで反映される |
| 共有イメージと仲間例のパネルは出さない | 暗記カードと意味チェックのどちらにも表示しない。核心イメージは連鎖だけを表示する |
| UI規範 | `DESIGN.md` の「熟語の核心イメージ」の項 |

`static/mode-q1.js` や `static/styles.css` を変更したら `index.html` のキャッシュバスターを上げる。

## 9. 検査スクリプト側に残っている固定値

`scripts/check-core-image-data.cjs` には、回帰を防ぐために内容を直接固定している箇所がある。**該当データを変更するときは検査も同時に直す**。

| 固定値 | 対象 | 意味 |
| --- | --- | --- |
| `cReasons` | C型の全 phrase と理由 | ここに無い未分類の熟語があると落ちる。C型を足す/やめるときに更新する |
| `expected2025_2Terminals` | `vocab_1_2025-2.json` 16件の連鎖末の gloss | 一度この16件だけ連鎖が未完成のまま公開された事故があり、その回帰を防ぐために固定している |
| `out` の sense 数上限（10） | `data/particle_images.json` | 用法の細分化が進みすぎた履歴があるため上限を設けている |

これ以外に総数（熟語数・セット数）を固定している箇所は無い。セットを追加しても件数では落ちない。
