# 暗記カード 実測計画

> 対象: `eiken-q1-practice` の暗記カード画面（STEP 1 flash）。
> 目的: UX摩擦監査・デザイン監査（2026-08-25）で挙げた指摘を、**実装前後で同じ手順・同じ指標**で比較できるようにする。
> 関連: [HOME_NEXT_ACTION_FIX_PLAN.md](HOME_NEXT_ACTION_FIX_PLAN.md) / [../DESIGN.md](../DESIGN.md)
> 状態: 計画（未実行）。作成日 2026-08-25。

## 1. なぜ測るか

監査の指摘は12枚のカードの実測に基づくが、標本が1セット・1画面幅に偏っている。実装の可否と効果を判断するには、次の2つが要る。

1. **分布としてのベースライン** — 「主操作が最大720px画面外」は最悪値であって、88枚中どれくらいの頻度で起きるかは未測定。
2. **合格基準** — 実装後に「良くなった」と言うための、事前に決めた閾値。

主観の入る余地を減らすため、**同じスクリプトを実装前と後で流し、同じJSONを出力して差分を見る**。

## 2. 測定対象

### 2-1. 標本

| 標本 | 内容 | 枚数 | 目的 |
|---|---|---:|---|
| 主標本 | 英検1級 2026年度第1回・全22設問×4枚 | 88 | 分布の把握。語源あり／核心イメージ／中間ブロックなしを自然な比率で含む |
| 補助標本A | 英検2級 2026年度第1回・第1〜3設問 | 12 | 級による構成差の有無 |
| 補助標本B | 英検準1級 2026年度第1回・第1〜3設問 | 12 | 同上 |

補助標本は「級で結論が変わらないこと」の確認用なので、全数は取らない。**級によって差が出た場合のみ**、その級で全数を取り直す。

### 2-2. 画面幅

| 幅 | 高さ | 根拠 |
|---:|---:|---|
| 320 | 640 | DESIGN.mdが320px幅での折り返しを規定している（学習計画パネルの項） |
| 375 | 812 | 主要な利用幅と想定（**仮説**。利用実態のデータはない） |
| 768 | 1024 | タブレット |
| 1280 | 800 | PC。`.wrap` の上限960pxが効く幅 |

全数（88枚）を測るのは **375px と 1280px** の2幅。320 と 768 は主標本のうち代表6枚（語源あり2／核心イメージ2／なし2）に限る。測定時間と得られる情報量の釣り合いから。

## 3. 測定項目

各項目は監査の指摘に1対1で紐づける。紐づかない項目は測らない。

| ID | 指標 | 定義 | 紐づく指摘 |
|---|---|---|---|
| M1 | 主操作の折り目からの距離 | `navTop - innerHeight`（正なら画面外、負なら画面内） | UX① |
| M2 | M1の振れ幅 | 標本内の `max(M1) - min(M1)` | UX① |
| M3 | カード高 | `.flash` の height | デザイン・反復 |
| M4 | 行の面積比 | 各 `.flashRow` の height ÷ `.flash` の height | UX② / デザイン・視覚階層 |
| M5 | 意味のタイポ | `.flashMeaning` の font-size / font-weight、および見出し語比 `meaningSize ÷ wordSize` | UX② |
| M6 | 本文の行幅 | 各本文要素の `width ÷ font-size`（em）。ラテン文字は `width ÷ (font-size × 0.5)` を ch の近似として併記 | デザイン・タイポグラフィ |
| M7 | 余白 | ①画面端 ②行ラベル→内容 ③行間 ④カード→操作 ⑤操作→カード番号 | デザイン・余白 |
| M8 | 塗りCTA数 | 背景が透明でない可視ボタンの数 | デザイン・視覚階層 |
| M9 | 小さすぎるタップ対象 | 可視ボタンのうち高さまたは幅が44px未満の件数 | アクセシビリティ |
| M10 | 横溢れ | `documentElement.scrollWidth > clientWidth` | レスポンシブ |
| M11 | ガード中のフィードバック | 送りボタン押下後、**同じボタン要素**を +100ms（ガード中）と +500ms（ガード明け）で比べ、`class` / `aria-disabled` / `disabled` / 背景色 / 不透明度のいずれかが異なるか | UX③ |
| M12 | 送り後に見出し語が見えるか | 送り直後に `.flashWord` が画面内に完全に収まっているか | UX① |

**測らないもの**: 学習効果、記憶定着、利用者の主観。これらはDOM実測では出せない。UX監査の「6. 検証」のユーザーテストで別途扱う。

## 4. 手順

### 4-1. 事前準備（必須）

測定はカードを送るため、`localStorage` の `resume`（途中保存）を上書きする。**測定前に退避し、測定後に必ず復元する。**

```js
// 退避
(() => {
  const keys = Object.keys(localStorage).filter(k => k.startsWith('eiken_q1_'));
  const bak = Object.fromEntries(keys.map(k => [k, localStorage.getItem(k)]));
  sessionStorage.setItem('__measure_bak__', JSON.stringify(bak));
  return { saved: keys.length };
})()
```

```js
// 復元（測定後に必ず実行し、戻り値の restored:true を確認する）
(() => {
  const bak = JSON.parse(sessionStorage.getItem('__measure_bak__') || 'null');
  if (!bak) return { restored: false, reason: 'backup missing' };
  Object.entries(bak).forEach(([k, v]) => localStorage.setItem(k, v));
  sessionStorage.removeItem('__measure_bak__');
  return { restored: Object.entries(bak).every(([k, v]) => localStorage.getItem(k) === v) };
})()
```

### 4-2. 起動

```powershell
py -3 -m http.server 8062 --bind 127.0.0.1
```

`.claude/launch.json` 経由でプレビューを開く場合はポートが変わるため、記録には**実際に測定したURL**を残す。

### 4-3. 測定の注意

- **カード送りは520ms以上あける**。[mode-q1.js:326](../static/mode-q1.js) の `FLASH_NAV_GUARD_MS = 450` により、それより速い操作は無視される（監査で実測済み）。
- **`document.fonts.ready` を待ってから測る**。Cormorant Garamond / Inter / JetBrains Mono の読み込み前後で高さと行幅が変わる。
- 幅を変えたら**リロードしてから**測る。sticky要素と折り返しの再計算漏れを避ける。
- ブラウザのズームは100%固定。
- **M11 は同じ要素の時間差で見る**。押下前後の別要素を比べると、押下フィードバックを `:active` などの疑似クラスだけで実装した場合にクラス名が変わらず、変化を検出できない。背景色と不透明度も署名に含める。
- **M12 は送り直後に測る**。カード送りでスクロール位置が持ち越されるため（4-4の実測を参照）、`M1` だけでは体験を捉えられない。
- **送りボタンまでスクロールしてから押す**。スクロールせずにプログラムから押すと持ち越しが起きず、M12が常に `true` になる（スクリプト検証時に実際にこの誤りを踏んだ）。
- ガード明けの待機を挟むため、1枚あたり約1秒かかる。主標本88枚で約2分（設問間の遷移を含む）。

### 4-4. 実測で判明した前提（2026-08-25）

カード送りでは**スクロール位置が持ち越される**。第1問で `scrollY = 909` の位置から「次のカード」を押した結果:

| | 値 |
|---|---:|
| 押下前 / 押下後の scrollY | 909 / **909（変化なし）** |
| 新しいカードの上端 | 484（画面外・上） |
| 画面上部に見えていた内容 | 「軽くする → 軽減した」（語源ブロックの途中） |

新しい語のカードが、見出し語を飛ばして途中から表示される。**M1（文書内の位置）はスクロール0を前提とした指標なので、この状態を検出できない**。M12を併せて測る理由。

### 4-5. 測定スクリプト

正本は [`scripts/measure-flashcard.js`](../scripts/measure-flashcard.js)。計画側にコピーを置くと両者が食い違うため、**本文には転記しない**。構文は `npm test` の `node --check` で検査する。

公開される関数:

| 関数 | 用途 |
|---|---|
| `backupFlashcardMeasurementState()` | 4-1の退避 |
| `restoreFlashcardMeasurementState()` | 4-1の復元。測定中に増えたキーも削除して元の状態に戻す |
| `measureQuestion("第1問", options?)` | 1設問（4枚）を測って配列で返す |
| `measureQuestions(["第1問", ...], options?)` | 複数設問をまとめて測る |

読み込みと実行:

```js

(async () => {
  const src = await (await fetch('scripts/measure-flashcard.js', { cache: 'no-store' })).text();
  (0, eval)(src);
  return { loaded: typeof window.measureQuestion, backup: window.backupFlashcardMeasurementState() };
})()
```

```js
// 主標本（1級2026-1の全22設問）
(async () => {
  const labels = Array.from({ length: 22 }, (_, i) => `第${i + 1}問`);
  return await window.measureQuestions(labels);

```

```js

window.restoreFlashcardMeasurementState()
```

## 6. 合格基準（実装後）

指摘ごとに、実装後の再測定で満たすべき値を先に決める。**測ってから基準を決めない。**

| 指摘 | 指標 | 合格基準 |
|---|---|---|
| UX① 主操作が画面外 | M1 | 375pxの**全88枚**で `M1 ≤ 0`（常に画面内） |
| UX① 位置が一定しない | M2 | `M2 ≤ 8px`（固定位置なら実質0） |
| UX① 送り後に見出し語が見えない | M12 | 送り後の全カードで `true` |
| UX① 例文訳が隠れない | 追加確認 | 固定バー導入時、`.flashExampleTranslation` の下端がバー上端より上にある |
| UX② 意味の弱さ | M5 | `font-size ≥ 22px` かつ `font-weight ≥ 600` かつ `vsWord ≥ 0.70` |
| UX③ 無反応窓 | M11 | 送りボタン押下後100msで `true`（クラスまたは `aria-disabled` が変化） |
| デザイン・行幅 | M6 | 日本語本文（意味・例文訳・パネル）が `em ≤ 40`、ラテン本文（例文）が `chApprox ≤ 75` |
| デザイン・余白 | M7 | `navToCounter ≥ 24px`、またはカード番号を `.itemHead` へ移動して当該間隔が消える |
| 回帰（階層） | M8 | `= 1`（現状維持） |
| 回帰（タップ対象） | M9 | 全幅で `0` 件 |
| 回帰（溢れ） | M10 | 全幅で `false` |

M4（面積比）には**閾値を置かない**。語源・核心イメージの分量はこのアプリの学習設計そのもので、DOM実測では適否を判定できない。UX監査の「検証後7」のユーザー観察を待つ。

## 7. 記録と報告

- 測定ごとに `{ 日付, コミットSHA, URL, ブラウザ, 幅, 標本, JSONパス }` を残す。
- Before / After は**同じコミット以外の差分を挟まない**。他の変更と混ぜると原因が切り分けられない。
- 合格基準を満たさなかった項目は、満たさなかった値のまま報告する。基準を後から緩めない。

## 8. リスク・未確認事項

- **進捗データを書き換える**。4-1の退避・復元を飛ばすと、途中保存が測定用のものに置き換わる。復元の戻り値 `restored: true` を毎回確認する。
- 主標本88枚の測定は、520msのガード待ちだけで約46秒、画面遷移を含めて**数分かかる**。途中で中断した場合も復元手順を実行する。
- 「375pxが主要な利用幅」は**仮説**。利用実態のデータはない。幅の重み付けを変える根拠が出たら本計画を改訂する。
- M6のch換算は `font-size × 0.5` の近似。厳密な比較が要る場合のみ、実文字幅の測定に切り替える。
- 補助標本A・Bは差の有無の確認用で、**級ごとの結論を出せる標本数ではない**。
- クラウド同期・生徒別ストレージ利用時は測定していない。ローカル匿名利用が前提。
