# トピック別表現集を出題形式に載せる実装計画

対象データ: `data/topic_phrases_1.json`（36トピック / 327項目）

確定方針:
1. 出典は公開可（`.gitignore` 対象にしない。通常どおりコミット・配信する）
2. 間隔復習は **1級の既存語彙と分ける**（独立プール）
3. 本番形式は **英語例文の空所補充**（各表現に例文を作る）
4. 5セットに分割
5. 同一問の誤答は **意味の方向が異なるものに限る**
6. 多語表現が「熟語」と表示される点は許容

## 1. 既存アプリのデータ契約（実装済みの制約）

| 制約 | 実装箇所 |

## 2. データ整備（生成前の前処理）

### 2-1. 表層形の正規化（**必須・35件**）
`en` に `/` `[ ]` `( )` `（略：…）` `（< …）` を含む項目が35件ある（例: `tariff / import tariff / import tax`、`basic [fundamental] human rights`、`information technology（略：IT）`、`prescription（< prescribe: ～を処方する）`）。この形のままだと選択肢と語句の対応づけ（`findItemForSurface` / `surfaces_match`）に失敗し、`check_q1_data.py` も通らない。

- 出題に使う表層形は**1つに確定**する（`tariff`、`basic human rights`、`information technology`、`prescription`）。
- 言い換え・略語・派生情報は `meaning` 末尾か `etymology`（暗記カードの「語源・なりたち」欄, `mode-q1.js:1917`）へ退避する。`（略：IT）` は `meaning` 側に「情報技術（略：IT）」として残すのが自然。

### 2-2. 重複の整理
- 英語表現が完全一致する2組（`economic deterioration`: 少子高齢社会/労働、`developing country`: 世界の貧困/世界の問題）は初出のみ採用 → **327 → 325項目**。
- 意味だけ重なる2組（`innovation` と `technological innovation` がともに「技術革新」、`discrimination` が2トピック）は**同一問に入れない**（同一問の意味重複は契約違反）。

### 2-3. type 判定
2語以上 → `idiom`（`phrase` フィールド）、1語 → `word`（32件）。誤答選択肢は同 type から優先的に選ばれるため、この振り分けが選択肢の質を決める。UI上「熟語」と表示される点は許容（方針6）。

### 2-4. 意味の方向タグ（**新規・325件の付与作業**）
方針5を機械的に守るため、各項目に `axis` を1つ付ける。

| 値 | 内容 | 例 |
| --- | --- | --- |
| `problem` | 問題・悪化・リスク | 労働力不足 / 税収の減少 / 年金制度の崩壊 |
| `cause` | 原因・背景・前提事実 | 医療の発達 / 核家族化 / 急激な人口増加 |
| `solution` | 対策・改善・望ましい結果 | 予防医学 / 高齢者の雇用 / 失業率の低下 |
| `concept` | 制度・組織・中立的な概念 | 医療制度 / 世界貿易機関 / 関税率 |

グルーピング規則:
- 同一問の4件は**原則すべて異なる `axis`** にする。
- トピック内に4種そろわない場合のみ、同一 `axis` を最大2件まで許容する。ただしその2件は**増減や良し悪しの方向が同じもの同士にしない**（「税収の減少」と「労働人口の減少」は不可、「税収の減少」と「高齢者の雇用」は可）。
- これでも条件を満たせない場合は、同一セット内の他トピックから補充する。

## 3. 例文づくり（最大の作業）

- **325件すべてに `example` と `exampleTranslation` を付ける**（暗記カードの例文欄に出る）。
- そのうち各問の**正答語句の例文が、そのまま本番形式の `stem` になる**。見出し表現を `( )` に置換し、その `exampleTranslation` を設問の `translation` に使う。stem用に完成度が要るのは 84問分の正答例文。
- 誤答が意味の方向で分かれている（§2-4）ため、例文には**方向を決める手がかり**（because / as a result / despite などの論理関係、増減を示す語、共起する主語）を必ず入れる。これがないと「文法的にはどれも入る」悪問になる。
- 既存の `scripts/enrich_flashcard_fields.py` / `scripts/curate_1_examples.py` と同じ役割分担（生成→検品）で進める。

## 4. セット分割（5セット・84問）

datasetId は **`eikentopic-set-1` 〜 `eikentopic-set-5`**。級プレフィックスを既存4級と別にすることで、間隔復習プール・誤答の意味プール・進捗が1級と完全に分離する（方針2）。ホーム画面には級タブが1つ増える。

| datasetId | テーマ（収録トピック） | 語句 | 問数 |
| --- | --- | --- | --- |
| `eikentopic-set-1` | 社会・人権・教育（少子高齢社会/現代人のモラル/都市化/プライバシー/言論の自由/女性の権利/教育/伝統文化/スポーツイベント） | 77 | 20 |
| `eikentopic-set-2` | 犯罪・法・情報（犯罪/刑務所/違法ダウンロード/インターネット/マスメディアと広告） | 42 | 11 |
| `eikentopic-set-3` | 国際・貿易・経済（世界の貧困/世界の飢餓・水問題/貿易と関税/世界経済のボーダーレス化/世界の問題/難民・移民の受け入れ） | 75 | 19 |
| `eikentopic-set-4` | 安全保障・環境・エネルギー（戦争と紛争/核兵器/テロリズム/自衛隊/化石燃料と再生可能エネルギー/原子力発電/森林破壊） | 61 | 16 |
| `eikentopic-set-5` | 科学技術・医療・労働（テクノロジー/宇宙開発/医療/再生医療/遺伝子組み換え作物/クローン/動物実験/労働/税） | 70 | 18 |

- 1問4件はトピック単位で切り出し、§2-4 の方向規則を満たす組み合わせを作る。トピックの端数は**同一セット内の近いトピックと合流**させる。
- 各セットで最大3件の端数が残る（合計11件）。ここは**同一セット内の既出表現を誤答として1回だけ再掲**して埋める（同一問には入れない）。語句ごとの進捗は `type:表層形` で共有される（`mode-q1.js:437-439`）ため、再掲しても間隔復習は二重にならない。
- 間隔復習が独立プールになったことで、意味チェックの誤答は**トピック表現同士**から作られる（325語プール）。1級の難単語とは混ざらない。

   → 級判定・独立プール化・音声パス `assets/audio/vocab/topic/set-N/` が通る。
2. `static/mode-q1.js:1349-1359` — `datasetSetKind` / `datasetSetLabel` に「テーマ別」を追加（未対応だと5セットとも「過去問」表示になる）。
3. **「英検◯◯ 大問1」固定文言の切り替え**（`:1015`, `:1055`, `:1156`, `:1289`, `:2493`）。テーマ別セットは大問1のデータではないため、`英検${shortLabel} 大問1 単語アプリ` のままだと「英検テーマ別 大問1 単語アプリ」になる。`manifest` の `shortLabel` を「1級テーマ別」とし、`大問1` の部分をセット種別で出し分ける（数行の修正）。

## 6. 実装手順

1. `data/topic_phrases_1.json` に `axis` を付与（§2-4）。表層形の正規化（§2-1）と重複整理（§2-2）もここで確定させる。
2. `scripts/build_topic_data.py` を追加。正規化済みリストを入力に、type判定 → セット割り → 方向規則を満たす1問4件のグルーピング → `data/questions_topic_set-N.json` / `data/vocab_topic_set-N.json` 出力までを一括生成（既存 `build_q1_*.py` と同じく、手編集ではなく再実行可能な生成物にする）。方向規則を満たせない組み合わせが残ったらエラーで落とす。
3. 例文・和訳325件を作成し、生成スクリプトの入力（別JSON）として保持。正答語句の例文から stem と translation を機械的に導出する。
4. `data/manifest.json` に5エントリ追加（`shortLabel` は「1級テーマ別」）、`mode-q1.js` の3箇所修正、`check_q1_data.py` 拡張。
5. 検証: `py -3 scripts/check_q1_data.py` → `py -3 -m http.server 8061` で1セットを暗記カード〜最終チェックまで通し、**間隔復習カードが1級と別に立ち、トピック表現だけが出る**ことを確認。長い選択肢の折返しをスマホ幅で確認（§7-1）。
6. `README.md` 更新（対象データ一覧、セット数 17 → 22、級テーブルに「テーマ別」行を追加）。
7. 後追い: `scripts/generate_tts_1.py` に倣って `assets/audio/vocab/topic/set-N/` に音声生成（無くても読み上げで動く）。
8. `graft build` でコンテキストグラフを再生成。

## 7. 実装中に確認する項目（判断待ちではない）

### 7-1. 選択肢・カードの表示崩れ
英語表現が長い（30字以上が43件、最長58字 `the practicality of investment in space-related technology`）。既存セットは1〜3語中心なので、
- 選択肢ボタン（`.choiceBtn` は `min-height:52px` の flex, `static/styles.css:980`）での折返し、
- ホームの設問カードが4語句を `" / "` 連結して表示する箇所（`static/mode-q1.js:1233`）
をスマホ幅を含めて実ブラウザで確認する。1セット作った時点で先に見る。

### 7-2. 音声ボタン
`DATASET_ID_RE` にマッチした時点で全語句にボタンが出る（`static/mode-q1.js:766`）。mp3 未生成の間は毎回404 → ブラウザ読み上げにフォールバックする（`:853-857`）。手順7でTTSを生成するまでは404が出る状態を許容する。

### 7-3. 例文325件の投入単位
一括作成か `set-1` から段階投入か。段階投入する場合は manifest 登録と `EXPECTED_IDS` を完成セットから順に増やす。
