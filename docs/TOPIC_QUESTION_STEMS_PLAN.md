# テーマ別セット：設問文を例文から独立させる実装計画

関連: [TOPIC_PHRASES_PLAN.md](TOPIC_PHRASES_PLAN.md)（初回実装） / [TOPIC_PHRASES_FIX_PLAN.md](TOPIC_PHRASES_FIX_PLAN.md)（例文とグルーピングの修正）

## 1. 目的

現在、本番形式の `stem` は**正答語句の例文をそのまま空所化したもの**（[build_topic_data.py:541-553](../scripts/build_topic_data.py)）。学習フローは「暗記カード → 意味チェック → 本番形式」なので、**直前のカードで読んだ文がそのまま設問に出る**。解くパートが理解の確認ではなく直前の記憶の再生になっている。

設問文を語句の例文とは別に用意し、その回で本当に使い分けられるかを試せるようにする。既存の大問1セット（過去問・模試）は設問文と語句の例文が別物なので、形式としてもそちらに揃う。

副次的な利点として、**4択が確定した状態で設問文を書ける**ようになる。今は例文を単独で書いてから4択に組むため、他の3件が入らない保証がしにくく、結果として誤答を意味の遠いトピックから取る形になっている（4件すべて同一トピックの問は84問中18問のみ）。設問文が具体的なら同一トピックの誤答でも正答が一意に決まるため、トピックの揃え方を当初設計へ戻せる。

アプリ側のコード変更は不要（`stem` は文字列として描画されるだけ, [mode-q1.js:2411](../static/mode-q1.js)）。

## 2. 方針

1. 設問文84本を**入力データ**として持つ（生成物にしない）。
2. **グルーピングを先に確定させてから設問文を書く**。`choose_groups` は正答（`group[0]`）も決めるため、後からグルーピングを変えると設問文が宙に浮く。順番を逆にすると84本の書き直しになる。
3. 確定後は**グルーピング結果を凍結ファイルとしてコミット**し、以後の再生成で組み合わせが動かないようにする。
4. 語句の例文324本はそのまま暗記カード用に残す（削除も作り直しもしない）。

## 3. データ設計

### 3-1. 凍結するグルーピング `data/topic_question_groups_1.json`（新規）
```json
{
  "meta": { "sets": 5, "questions": 84 },
  "groups": [
    { "set": 1, "q": 1, "answer": "少子高齢社会::advancement of medicine",
      "distractors": ["現代人のモラル::materialism", "少子高齢社会::aging society", "少子高齢社会::healthcare system"] }
  ]
}
```
キーは既存の `example_key`（`topic::en`, [build_topic_data.py:376](../scripts/build_topic_data.py)）と同形式。選択肢の並び順は現状どおり `answerIndex` を生成側で決める（凍結対象は「どの4件か・どれが正答か」だけ）。

### 3-2. 設問文 `data/topic_question_stems_1.json`（新規）
```json
{
  "meta": { "questions": 84 },
  "stems": [
    { "answer": "少子高齢社会::advancement of medicine",
      "stem": "…( )… ",
      "translation": "…" }
  ]
}
```
設問番号ではなく**正答のキー**で引く。番号はセット内の並びで変わりうるため。

## 4. 生成側の変更（`scripts/build_topic_data.py`）

1. `load_groups()` を追加。凍結ファイルがあればそれを使い、無ければ従来どおり `choose_groups()` で作る（初回の凍結ファイル生成用に `--freeze` オプションを付ける）。凍結ファイルのキーが現在の語句一覧と一致しなければエラーで落とす（`load_examples` の不一致チェックと同じ方式, [:397-401](../scripts/build_topic_data.py)）。
2. `load_stems()` を追加。84件すべてが揃っていること、`( )` をちょうど1つ含むこと、正答の表層形を含まないことを読み込み時に検査する。**1件でも欠けたらエラーで落とす**（例文へ暗黙にフォールバックしない）。
3. `build_set()` の stem 生成（`:541-553`）を、例文からの導出から `stems` の参照に差し替える。`translation` も同ファイルから取る。

## 5. 検証の追加（`scripts/check_q1_data.py`）

テーマ別セット向けに以下を追加する。既存の検証（stem の `( )` が1つ／正答表層形が stem に出ない／stem 骨格の全体一意／例文骨格の一意／axis 制約）はそのまま残す。

1. **stem の骨格が、その設問の4語句いずれの例文の骨格とも一致しないこと**（例文への逆戻りを検知する。これが今回の中心的な回帰テスト）。
2. **stem の語数が15語以上**であること。既存1級の stem は中央値24語（15〜45語）に対し、現在のテーマ別は中央値10語（8〜14語）と短く、手がかりを入れる余地がない。
3. 凍結ファイルと生成物の整合（`build_topic_data.py` 側で担保するため、検証は任意）。

## 6. 設問文84本の作成基準

- **長さ**: 20〜40語、1〜3文。既存1級の中央値24語に合わせる。
- **手がかり**: 空所の前後に、正答だけが成立する具体的な根拠を置く（因果関係、増減や数値、共起する主語・動詞、対比）。抽象的な「〜と社会への影響」型は不可。
- **一意性**: 同一問の誤答3件を空所に入れたとき、意味的に成立しないこと。`scripts/review_topic_questions.py` の出力（4通りを並べた比較）で毎問確認する。**これを完了条件にする**（機械では判定できない）。
- **場面**: その語句の例文とは別の場面にする（暗記カードと同じ文脈にしない）。
- **和訳**: 1本ずつ書く。定型の言い換えにしない。

## 9. 判断が要る点

1. **グルーピングを見直すか**。設問文を独立させると同一トピック内の誤答でも一意に決められるため、「4件すべて同一トピック」（現在18/84問）へ寄せ直せる。ただし §2-2 のとおり**設問文を書く前に決める必要がある**。あわせて、`development of technology` が set-4 の16問中4問に出るなどの再掲の集中も、ここで一緒に解消できる。
2. 設問文を84本だけにするか、将来のグルーピング変更に備えて語句324件すべてに用意するか。84本を推奨（不足時はビルドが落ちるので事故にはならない）。
3. 語句の例文324本の扱い。暗記カード用に残す前提だが、設問文と重複感が出る場合は例文側を短くする選択もある。
